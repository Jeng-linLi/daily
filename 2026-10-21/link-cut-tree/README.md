# Link-Cut Tree（動態樹 / LCT）

`solution.py`（Python 3 標準庫）與 `solution.cpp`（C++17）行為完全一致：
有 stdin 走 IO 模式，沒有 stdin 就跑內置斷言並輸出 `all tests passed`。

---

## 題意

有 n 個節點（編號 1..n），每個節點有一個整數權值。一開始整張圖**沒有邊**。
依序處理 q 個操作，動態地連邊、斷邊（整張圖始終保持森林），
並在任意時刻查詢／修改「u 到 v 這條路徑」上的資訊。

| 操作碼 | 參數 | 說明 |
|---|---|---|
| 1 | `u v` | 連邊（u、v 已連通則忽略，避免成環） |
| 2 | `u v` | 斷邊（該邊不存在則忽略） |
| 3 | `u v` | 路徑查詢：輸出「權值和 最大值 最小值 邊數」；不連通輸出 `-1` |
| 4 | `u v w` | 路徑修改：u→v 上每個點權加 w（不連通則忽略） |
| 5 | `u v` | 連通性：輸出 `1` / `0` |
| 6 | `u x` | 單點改值：把 u 的權值設成 x |
| 7 | `u v` | 輸出路徑上的點權（u→v 的順序）；不連通輸出 `-1` |

## 輸入格式

```
n                    點數（0 ≤ n ≤ 300；負數視為 0）
v1 v2 ... vn         一行 n 個初始權值（夾到 [-10^6, 10^6]）
q                    操作數（0 ≤ q ≤ 400；負數視為 0）
op ...               q 行，每行一個操作
```

全部 token 以空白分隔；遇到非整數 token 就當成「輸入到此為止」，缺值補預設。
編號不在 1..n 的操作直接忽略（不產生輸出）。

## 輸出格式

```
每個 op ∈ {3, 5, 7} 輸出一行結果（共 k 行）
```

op 3 輸出四個整數；op 5 輸出一個 0/1；op 7 先輸出路徑長度 cnt，再輸出 cnt 個點權。

## 輸入輸出示例

輸入：

```

```

輸出：

```

1
1
30 13 1 3
0

```

說明：連成鏈 1-2-3-4 後，路徑 1→4 的和是 10、最大 4、最小 1、邊數 3；
路徑點權是 `1 2 3 4`；1 與 3 連通。把 2→3 這段加 10 後權值變成 `1 12 13 4`，
路徑和 30、最大 13。斷掉邊 (2,3) 之後 1 與 4 不連通，查詢得到 `-1`。

## 思路

### 1. 為什麼需要 LCT

靜態樹上做路徑查詢，樹鏈剖分（heavy-light decomposition）就夠了；
但它**不能加邊刪邊**。LCT 用「**實鏈剖分**」解決這件事：
把每個點的兒子中**至多一個**標成「實邊」，其餘是「虛邊」。
實邊串成的鏈用一棵 **splay** 維護（鍵是中序對應的樹上深度），
虛邊只記錄「這棵 splay 的根的父親是誰」（path-parent，單向）。

於是「森林」被拆成一棵棵 splay。兩個關鍵操作：

- **`access(x)`**：把根到 x 的路徑整條變成實鏈。
  反覆「splay(x) → 把 x 的右子樹換成上一輪處理過的鏈 → 往上跳 path-parent」。
  做完 x 所在的那棵 splay 就恰好含根到 x 的全部節點，且 x 是 splay 根。
- **`makeroot(x)`**：`access(x)` 之後翻轉整棵 splay（懶標記 `rev`），
  把 x 變成整棵樹的**代表根**。這正是 LCT 能做到「無根樹任意路徑」的原因。

有了 `split(u,v) = makeroot(u); access(v)`，v 的那棵 splay 就**恰好**是 u..v 的路徑，
路徑查詢／修改全部退化成「對一個 splay 根做一次 O(1) 讀取 / O(log n) 懶標記」。

### 2. `access` 的正確寫法

```python
def access(x):
    last = 0
    y = x
    while y:
        splay(y)
        ch[y][1] = last
        pushup(y)
        last = y
        y = fa[y]
    splay(x)
```

注意**不要**額外寫 `fa[last] = y`：迴圈最後一步的 `y = fa[y]` 本身就讓
下一輪的 `ch[新 y][1] = last` 滿足 `fa[last] == 新 y`。多寫一次反而容易寫反。

### 3. `cut` 的判斷條件

`makeroot(u); access(v)` 之後，v 是 splay 根、整條 path 都在它的子樹裡。
u 是「直接相鄰」的充要條件是：

```
ch[v][0] == u  且  ch[u][1] == 0
```

前者表示 u 是 v 的前驅，後者表示 u..v 之間沒有第三個點。少任何一個都會誤砍。

### 4. 懶標記

- `rev[x]`：翻轉（makeroot 用）
- `lazy[x]`：路徑加值（`pushadd` 時 `sum[x] += w * sz[x]`，所以每棵 splay 都要維護子樹大小）

下推順序固定為「先 rev 再 add」。取 max / min 時，哨兵節點 0 的
`mx[0] = -INF`、`mn[0] = +INF` 必須先設好，否則答案會被 0 污染。

### 5. 驗證方式

每次 op 3 / 5 / 7 都用一份獨立的 **O(n) 暴力參考實作**
（鄰接表 + BFS 找路徑）同步跑一遍，並 `assert` 兩者結果完全相同。
路徑的**順序**（op 7）也一併比對 —— 這能抓出 `makeroot` 沒做對、
或 `rev` 標記忘了下推這類「總和對但順序錯」的 bug。

## 複雜度

| 操作 | 複雜度 |
|---|---|
| link / cut | 均攤 O(log n) |
| 路徑查詢 / 路徑修改 | 均攤 O(log n) |
| 單點改值 | 均攤 O(log n) |
| 空間 | O(n) |

## 應用場景

- 動態連通性：網路拓撲變動（連線／斷線）下的即時連通查詢
- 線上維護生成樹：邊權會改、邊會加刪的最小生成樹（動態 MST）
- 交通路網：施工封路（cut）與新路開通（link）後的兩地瓶頸路段統計
- 版本管理：分支合併圖上查詢兩版本之間的修改總量
- 遊戲伺服器：動態變化的地圖傳送網路上的路徑統計
