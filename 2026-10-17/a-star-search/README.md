# A* 與 IDA*（啟發式搜索）

`solution.py`（Python 3 標準庫）與 `solution.cpp`（C++17）行為完全一致：
有 stdin 走 IO 模式，沒有 stdin 就跑內置斷言並輸出 `all tests passed`。

---

## 題意

輸入分三段，一次全部做完；每段都把「啟發式搜索」與「無資訊的最優對照組」一起跑並對拍。

1. **網格最短路**：`R×C` 格子，`#` 是障礙，四方向移動、每步代價 1。
   A*（曼哈頓距離啟發）vs **BFS**，比較最短路長度與展開節點數。
2. **帶權圖最短路**：`n` 點 `m` 條有向邊（邊權非負），外加每個點的啟發值 `h[v]`。
   A* vs **Dijkstra**，比較最短路長度與展開節點數。
3. **八碼難題**：3×3 棋盤，用 **IDA\*** 求最少步數，
   與「從目標局面 BFS 出來的精確距離」對照（BFS 只做到深度 12，查不到就標記未知）。

## 輸入格式

```
R C                網格（0 ≤ R, C ≤ 20）
<row 0>            每行一個 token，只由 '.' 與 '#' 組成
...                長度不足補 '.'，非法字元視為 '#'
<row R-1>
sr sc tr tc        起點與終點（會被夾到合法範圍內）
n m                帶權圖（0 ≤ n ≤ 40，0 ≤ m ≤ 200）
u v w              m 條邊，端點超出範圍的直接丟棄，w 夾到 [0, 1000]
...
s t                源點與終點
h[0] .. h[n-1]     每個點的啟發值
<board>            9 位數字（0 代表空格）；不是 0–8 的排列就用目標局面
```

全部 token 以空白分隔；遇到非整數 token 就當成「輸入到此為止」，缺值補預設。

## 輸出格式（共 4 行）

```
1. 網格：  A*距離 A*展開數 BFS距離 BFS展開數
2. 帶權圖：A*距離 A*展開數 Dijkstra距離 Dijkstra展開數
3. 八碼：  IDA*步數 IDA*展開數 BFS對照距離
4. ok 旗標
```

特殊值：距離 `-1` 表示不可達；八碼 `-1` 表示**不可解**（奇偶判定，不展開任何節點）、
`-2` 表示**超出 50 萬節點預算**；第 3 行的對照距離 `-1` 表示「深度超過 12，未知」。

`ok = 1` 的條件：網格 A* 與 BFS 距離相同、帶權圖 A* 與 Dijkstra 距離相同、
八碼 IDA* 與 BFS 對照相同（對照未知時略過）。
若輸入的 `h` 不可採納，A* 會給出次優解，`ok` 就會是 0 —— 這正是設計上要暴露的現象。

## 思路

### A*：用 `f = g + h` 排序

優先佇列依照 `f = g + h`（已花代價 + 預估剩餘代價）由小到大取出節點。

- `h ≡ 0` 時 A* 退化成 Dijkstra —— 就是本題的對照組。
- `h` **可採納**（`h(v) ≤ 真實距離 d(v,t)`）且 **一致**（`h(u) ≤ w(u,v) + h(v)`）時，
  A* 保證第一次取出終點即為最短路。網格四方向 + 曼哈頓距離正好滿足兩者
  （障礙只會讓真實距離變長，所以曼哈頓距離仍是下界）。
- A* 的價值在於**展開更少節點**：`h` 越準，搜索越像「直接朝終點走」。

為了讓 Python 與 C++ 的展開數一模一樣，排序鍵固定為 `(f, h, 節點編號)`，
鄰居枚舉順序固定為 上 / 下 / 左 / 右。

> 可以證明 A* 展開的節點數 ≤ BFS：A* 只會展開 `g + h ≤ d*` 的節點，
> 而 `h ≥ 0` 保證 `g ≤ d*`；BFS 則會把距離 `< d*` 的節點全部展開。

### IDA*：迭代加深 + 用「超標多少」當下一輪門檻

A* 要存 open / closed 表，八碼難題的狀態數（181440）還撐得住，
但換成 15-puzzle 就會爆。IDA* 用 DFS 換空間：

1. 設門檻 `bound`，DFS 只展開 `f = g + h ≤ bound` 的節點；
2. 這輪找不到就記下「最小的超標值」當下一輪的 `bound`，從頭再搜一次；
3. 門檻只增不減、且 `h` 可採納 ⟹ **第一次找到的解就是最優解**。

空間只要 `O(最長路徑)`，代價是重複搜索（但每輪都被 `h` 砍掉大半分支）。
本題的 `h` 用 **曼哈頓距離 + 線性衝突**：

- 曼哈頓距離：每塊磁磚至少要走的步數下界；
- 線性衝突：同一行（列）裡有兩塊磁磚的目標也在這一行（列）、但左右（上下）順序相反時，
  它們必定要「繞出去」一次，至少多花 2 步。

### 八碼難題的可解性

3×3 棋盤寬度為奇數，所以「逆序數（不含空格）為偶數」⟺ 可解。
不可解時直接回報 `-1`，一個節點都不展開。

## 複雜度

| 項目 | 時間 | 空間 |
|---|---|---|
| 網格 A* / BFS | 最壞 O(R·C) | O(R·C) |
| 帶權圖 A* / Dijkstra | O((n + m) log n) | O(n) |
| IDA* | O(b^d)（`b` 分支數、`d` 解答深度） | O(d) |
| 八碼 BFS 對照（深度上限 12） | O(狀態數) ≈ 1.3 萬 | 同左 |

---

## 應用場景

- **A\***：遊戲 NPC 尋路（網格 / 導航網）、地圖導航（真實路網 + 直線距離或
  landmark 啟發）、機器人與機械手臂路徑規劃、拼圖 / 魔方的狀態空間搜索、
  文字校對的「最短編輯腳本」搜索
- **權衡**：`h` 越強（越接近真實距離）展開越少，但算 `h` 本身也要時間；
  `h = 0` 是 Dijkstra（最穩、展開最多）；`h` 過強且不可採納則會得到次優解
  —— 實務上常用「加權 A\*」（`f = g + ε·h`）故意換取速度與次優解
- **IDA\***：狀態空間大、記憶體吃緊時的首選（15-puzzle、TSP 的分支限界），
  也是「迭代加深 + 啟發剪枝」這個通用框架的典型代表；
  「迭代加深」本身在博弈樹（深藍、象棋 AI）裡也是標準配備

## 輸入輸出示例

輸入：

```
4 5
.....
.###.
.....
.....
0 0 3 4
5 6
0 1 4
0 2 1
2 1 1
1 3 2
2 3 5
3 4 3
0 4
7 5 6 3 0
123450786
```

說明：網格有兩格寬的牆，從左上角走到右下角；
帶權圖的最短路是 `0→2→1→3→4 = 1+1+2+3 = 7`，`h` 給的正好是真實距離；
八碼局面 `123450786` 只要把空格往下移一步就完成。

輸出：

```
7 8 7 17
7 5 7 5
1 3 1
1
```

逐行解讀：

1. 網格：A* 與 BFS 都得到距離 7，但 A* 只展開 **8** 個節點、BFS 展開 **17** 個
   —— 曼哈頓啟發把搜索集中在通往終點的方向
2. 帶權圖：A* 與 Dijkstra 都是距離 7；這裡 `h` 恰好等於真實距離，
   所以 A* 沿著最短路直線前進（5 個節點），Dijkstra 也剛好是 5
   （若把 `h` 全改成 0，兩行數字會完全一樣）
3. 八碼：IDA\* 得到 1 步、展開 3 個節點，與 BFS 對照的 1 步一致
4. `ok = 1`

再一個不可解的例子（把 `7 5 6 3 0` 那行之後的 board 換成 `213456780`，逆序數為 1）：

```
3
-1 0 -1
```

（第 3 行：`-1` = 不可解、展開 0 個節點、`-1` = BFS 對照也查不到。）

## 驗證方式

兩個檔案都內建了：

- 網格固定用例（空地 / 帶牆 / 目標被完全圍住 / 空輸入 / 單行）
- 帶權圖固定用例：`h = 0` 時 A* 必須等於 Dijkstra、真實距離當 `h` 時展開數不增加、反向不可達
- 八碼固定用例（目標局面 / 一步 / 不可解 / 線性衝突的值）
- 隨機對拍 300 組：隨機迷宮 + 隨機帶權圖（啟發值取真實距離的 0 / 1/2 / 3/4 / 1 倍，
  保證可採納且一致）+ 從目標隨機走 ≤ 9 步產生的局面
- 深度 10 / 12 的八碼局面，驗證 IDA* 與 BFS 對照一致

跑法：

```bash
python solution.py                 # 無 stdin → all tests passed
g++ -std=c++17 -O2 solution.cpp -o a.exe && ./a.exe
```
