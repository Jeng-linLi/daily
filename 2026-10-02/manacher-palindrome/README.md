# Manacher 算法：最長回文子串（Longest Palindromic Substring）

| 項目 | 內容 |
|---|---|
| 目錄 | `2026-10-02/manacher-palindrome` |
| 語言 | Python 3（標準庫） / C++17 |
| 考點 | Manacher、中心擴展、回文半徑複用 |
| 複雜度 | 時間 **O(n)**，空間 **O(n)** |

## 題意

給定字串 `s`，求：

1. 最長回文子串的長度；
2. 最長回文子串本身（若有多個同長度，取**最靠左**的）；
3. 回文子串的總數（不同位置的同一內容算不同子串）；
4. 奇回文半徑陣列 `d1`；
5. 偶回文半徑陣列 `d2`。

## 思路

**中心擴展**最直觀：枚舉 `n` 個奇中心與 `n` 個偶中心，各自往兩邊擴。最壞 O(n²)（例如 `"aaaa…a"`）。

Manacher 的洞見是：**已經算過的回文可以被複用**。維護當前「右端最遠」的回文區間 `[l, r]`，
處理中心 `i` 時：

- 若 `i` 落在 `[l, r]` 內，取 `i` 關於回文中心的**鏡像位置** `j`，則 `i` 處的半徑
  至少是 `min(d[j], r − i + 1)` —— 超出右界的那部分並不保證對稱，必須老實再往外擴；
- 若 `i > r`，從最小半徑開始擴。

因為 `[l, r]` 的右端只會單調右移，`while` 迴圈在整個過程中的總執行次數是 O(n)，攤銷下來就是 O(n)。

半徑定義（cp-algorithms 的寫法）：

| 陣列 | 中心 | 最長回文長度 | 該中心的回文個數 |
|---|---|---|---|
| `d1[i]` | 字元 `i` 本身（奇） | `2·d1[i] − 1` | `d1[i]` |
| `d2[i]` | `i−1` 與 `i` 之間的間隙（偶） | `2·d2[i]` | `d2[i]` |

半徑同時也是「以該中心形成的回文個數」，所以

```
回文子串總數 = sum(d1) + sum(d2)
```

這是 Manacher 一個很漂亮的副產品，比枚舉所有子串快一個數量級。

取最長回文時要注意：長度相同必須取最靠左的，因此更新條件是**嚴格 `>`**，讓先掃到的先佔住。

## 輸入格式

```
s       ← 第一行即為待處理字串（空字串請輸入一個只有換行的資料）
```

## 輸出格式

```
第 1 行：最長回文子串長度
第 2 行：最長回文子串（長度為 0 時輸出空行）
第 3 行：回文子串總數
第 4 行：d1 陣列，空格分隔（n = 0 時輸出空行）
第 5 行：d2 陣列，空格分隔（n = 0 時輸出空行）
```

## 示例

輸入：

```
cbbd
```

輸出：

```
2
bb
5
1 1 1 1
0 0 1 0
```

解釋：

- `d1 = [1,1,1,1]`：四個單字元各 1 個奇回文，共 4 個；
- `d2 = [0,0,1,0]`：只有 `i = 2`（`b` 與 `b` 之間的間隙）形成偶回文 `"bb"`，共 1 個；
- 回文子串總數 = 4 + 1 = 5（`c`、`b`、`b`、`d`、`bb`）；
- 最長回文 = `"bb"`。

另一個例子 `abacdc` 中，`"aba"` 與 `"cdc"` 長度都是 3，程式取最靠左的 `"aba"`。

## 怎麼跑

```bash
echo cbbd | python solution.py
g++ -std=c++17 -O2 -Wall solution.cpp -o solution && echo cbbd | ./solution
```

無 stdin 輸入時運行內置斷言測試：Manacher 與 O(n²) 中心擴展、O(n³) 暴力枚舉三方對拍
（含空字串、單字元、全同字元、無回文、偶回文最長等邊界），通過會輸出 `all tests passed`。
