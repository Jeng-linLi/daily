# 開放尋址哈希表與 LRU Cache（Open Addressing Hash Table & LRU Cache）

| 項目 | 內容 |
|---|---|
| 目錄 | `2026-10-05/hash-table-open-addressing` |
| 語言 | Python 3（標準庫） / C++17 |
| 考點 | 開放尋址、線性 / 二次 / 雙重探測、墓碑刪除、負載因子再散列、LRU（哈希 + 雙向鏈表） |
| 複雜度 | 哈希表均攤 **O(1)** 增刪查，空間 **O(cap)**；LRU `get` / `put` 均 **O(1)**，空間 **O(capacity)** |

## 題意

實現一個**不用鏈地址法**的哈希表（`string -> int`），支持：

1. `put(key, value)` 插入 / 更新；
2. `get(key)` 查詢，返回 `(是否命中, 值)`；
3. `erase(key)` 刪除；
4. 三種探測策略：線性探測 / 二次探測 / 雙重散列；
5. 負載因子（含墓碑）超過 0.5 時自動擴容再散列；
6. 統計探測次數，直觀比較三種策略的聚集程度。

另外實現一個 **LRU Cache**（哈希表 + 雙向鏈表），`get` / `put` 都要 O(1)。

## 思路

### 為什麼刪除要用墓碑（tombstone）

開放尋址裡，查找是沿著探測序列一路走到**第一個 EMPTY 槽**才宣告失敗。
如果刪除時直接把槽位設回 EMPTY，等於把這條探測鏈**截斷**，鏈後方的元素就永遠查不到了。

所以刪除改成標記 `DELETED`：

- 查找遇到 `DELETED` **繼續往前走**（不能停），但要記住第一個 `DELETED` 的位置，插入時可複用；
- 插入一路掃到 `EMPTY`，再回頭用第一個墓碑。

### 三種探測策略

| 策略 | 第 i 次探測位置 | 特性 |
|---|---|---|
| 線性探測 | `(h + i) mod M` | 緩存友好（連續記憶體），但有**一次聚集**：佔用區塊越長越慢 |
| 二次探測 | `(h + i²) mod M` | 消除一次聚集，仍有**二次聚集**（同哈希值走同一條序列） |
| 雙重散列 | `(h + i·(1 + h' mod (M−1))) mod M` | 步長與質數 M 互質，可走遍全表，聚集最少，緩存局部性較差 |

二次探測的正確性：當表長 `M` 為質數時，`i² mod M` 恰好取到 `(M+1)/2` 個不同值；
若負載因子 ≤ 0.5，空槽至少 `M/2` 個。兩個集合的大小和 `> M`，必有交集 —— **保證**找得到空位。

### 負載因子為什麼卡在 0.5

一來保證上面二次探測的正確性，二來讓平均探測次數維持在常數量級：

| 策略 | 成功查找（α = 0.5） | 失敗查找（α = 0.5） |
|---|---|---|
| 線性探測 | ≈ 1.5 次 | ≈ 2.5 次 |
| 雙重散列 | ≈ 1.39 次 | ≈ 2.0 次 |

跑 IO 模式時把第 3 行（累計探測次數）印出來，就能直接比較三種策略的差距。

### LRU Cache

哈希表負責 O(1) 定位，雙向鏈表負責 O(1) 維護「最近使用順序」：

- 頭哨兵之後是**最久未使用**，尾哨兵之前是**最近使用**；
- `get` 命中 → 摘下節點、掛到尾端；
- `put` 已存在 → 改值並掛到尾端；不存在且已滿 → 淘汰頭部後的第一個節點。

## 輸入格式

```
mode                      ← linear | quadratic | double
cap                       ← 初始容量（會被提升到 >= 2 的質數）
m                         ← 哈希表操作數
m 行：put key value | get key | del key
lru_cap                   ← LRU 容量
q                         ← LRU 操作數
q 行：put key value | get key
```

## 輸出格式

```
第 1 行：哈希表最終容量
第 2 行：存活元素個數
第 3 行：累計探測次數
第 4 行：所有元素，按 key 字典序，k:v 以空白分隔（空表輸出空行）
接著每個 get 一行：1 <value>（命中）或 0 -1（未命中）
再一行：LRU 目前大小
再一行：LRU 內容，由最久未使用到最近使用（空則空行）
再接著每個 LRU get 一行：<value> 或 -1
```

## 示例

輸入：

```
linear 8 7
put a 1
put b 2
get a
put i 9
del a
get a
get i
3 5
put x 1
put y 2
get x
put z 3
get y
```

輸出：

```
11
2
9
b:2 i:9
1 1
0 -1
1 9
3
x:1 z:3 y:2
1
2
```

解釋：

- 初始容量 8 會被提升到質數 11；
- 刪掉 `a` 之後 `get a` 是 `0 -1`，但同一條探測鏈上的 `i` 依然查得到 `1 9` —— 這正是墓碑的作用；
- LRU 容量 3：`put x` → `put y` 後順序是 `y, x`；`get x` 把 x 刷成最近使用 → `y, x`；
  `put z` 時未滿（2 < 3）不淘汰 → `y, x, z`；`get y` 再把 y 刷到尾端 → `x, z, y`，
  所以最後印出 `x:1 z:3 y:2`；
- 兩次 LRU `get` 分別得到 `x = 1`、`y = 2`。

## 備註

雜湊函數刻意用**確定性的多項式雜湊**（基數 131、截斷到 32 位無號），
而不是 Python 內建的 `hash()` —— 後者對字串是隨機加鹽的，每次進程結果都不同，
這樣才能讓 Python 與 C++ 兩個版本的 IO 輸出逐字節一致（僅對 ASCII 保證一致：
Python 是逐碼點、C++ 是逐位元組）。
