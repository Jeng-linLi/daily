# 掃描線 + 線段樹：求 n 個軸對齊矩形的聯集面積（Union Area）

`solution.py`（Python 3 標準庫）與 `solution.cpp`（C++17）行為完全一致：
有 stdin 走 IO 模式，沒有 stdin 就跑內置斷言並輸出 `all tests passed`。

---

## 題意

給定 n 個**軸對齊**（axis-aligned）的矩形，第 i 個矩形的左下角與右上角
分別是 `(x1[i], y1[i])` 與 `(x2[i], y2[i])`，其中 `x1[i] < x2[i]`、`y1[i] < y2[i]`。

求這 n 個矩形**聯集**（union）的面積 —— 也就是把重疊部分只算一次的總面積。

限制：`1 ≤ n ≤ 100000`，`|座標| ≤ 10^9`。

## 輸入格式

```
n
x1_1 y1_1 x2_1 y2_1
x1_2 y1_2 x2_2 y2_2
...
x1_n y1_n x2_n y2_n
```

## 輸出格式

一行，輸出聯集面積（整數）。

任何結構性錯誤（n 越界、座標超界、矩形退化成線段或點、
輸入缺 token、非整數）輸出 `error`。

## 輸入輸出示例

輸入：

```
2
0 0 4 3
2 1 6 5
```

輸出：

```
24
```

驗算：第一個矩形面積 `4 × 3 = 12`；第二個矩形面積 `4 × 4 = 16`；
重疊區域是 `[2,4) × [1,3)`，面積 `2 × 2 = 4`。
由容斥：聯集 = 12 + 16 − 4 = **24**。

## 思路

### 1. 為什麼不能直接加總

矩形彼此可能重疊，直接把面積相加會重複計算。
樸素做法是「格點化」：把所有 x、y 座標收集起來排序，
把平面切成 O(n²) 個小格子再逐格判斷 —— 格子數太多，O(n²) 不可行。

### 2. 掃描線（sweep line）

讓一條垂直線從左往右掃過 x 軸。
對每個矩形 `(x1, y1, x2, y2)` 產生兩個事件：

| 事件 | 動作 |
|---|---|
| `(x1, +1, [y1, y2))` | 進入矩形，把 y 區間 `[y1, y2)` 的覆蓋次數 +1 |
| `(x2, −1, [y1, y2))` | 離開矩形，把 y 區間 `[y1, y2)` 的覆蓋次數 −1 |

相鄰兩個事件的 x 之間，覆蓋情況完全不變 —— 這就是一個「條帶」（slab）。
若條帶寬為 `dx`、此時 y 方向的聯集長度為 `L`，則該條帶的面積 = `dx × L`。
把所有條帶的面積加起來就是答案。

> 所以問題變成：**動態維護一組 y 區間的聯集長度**。

### 3. 座標壓縮 + 線段樹

把所有出現過的 y 座標排序去重，得到 `ys[0..m-1]`。
線段樹的葉子不是「點」而是「基本區間」 `[ys[i], ys[i+1])`，共 m − 1 個。
節點維護兩個量：

| 變數 | 意義 |
|---|---|
| `cnt` | 完整覆蓋此區間的「矩形數」（不下傳的覆蓋次數） |
| `length` | 此區間內目前被覆蓋的總長度 |

更新規則（經典的「覆蓋次數」寫法）：

```
若 cnt > 0      → length = 區間的實際長度（整段被蓋住）
否則若為葉子    → length = 0
否則            → length = 左子 + 右子
```

根節點的 `length` 就是當前整個 y 軸的聯集長度。

### 4. 為什麼不需要 push-down

這裡刻意不做 lazy 下傳：`cnt` 記錄的是「有多少個矩形完整覆蓋了這個節點」，
而 deeper 的 `cnt` 記錄的是「在父節點未被完整覆蓋的前提下，
額外覆蓋此區間的矩形數」。當 `cnt` 由正變 0 時，
子節點的 `length` 早已包含了所有下層更新，直接相加即可。
這是矩形聯集面積的標準寫法。

### 5. 精度與整數性

所有座標都是整數，條帶寬度與聯集長度也都是整數，
所以面積一定是整數 —— 直接用整數運算即可，**不需要浮點數**，
也沒有精度誤差問題（C++ 端用 `long long`，最大面積 4 × 10^18 仍在範圍內）。

### 6. 實作要點

- **事件排序**：以 `(x, delta, y1, y2)` 為鍵排序，同一個 x 的事件必須
  **一起處理完**才能進入下一個條帶，否則會把同一個 x 上的進出混算。
- **y 區間是半開的**：`[y1, y2)`。若寫成閉區間，相鄰但只是「共享邊界」的
  矩形會被誤判成重疊。壓縮後更新的是基本區間索引 `[idx(y1), idx(y2))`。
- **線段樹的長度基準**：節點 `[l, r)` 對應的實際 y 長度是 `ys[r] − ys[l]`
  （不是基本區間個數），因為座標不一定等距。

## 複雜度

| 項目 | 複雜度 |
|---|---|
| 座標壓縮 + 事件排序 | 時間 O(n log n) |
| 2n 次線段樹更新 | 時間 O(n log n) |
| 總計 | 時間 O(n log n) |
| 空間 | O(n) |
| 參考實作（逐格累加，對拍用） | O(n³) |

## 驗證方式

- **固定用例**：單一矩形、不重疊、部分重疊、完全包含、完全相同、
  十字形、負座標、共享邊界、三個錯開矩形 —— 全部手算驗證；
- **隨機對拍**：220 組小案例 + 20 組中型案例，
  與「座標壓縮後逐格累加」的參考實作比對；
- **退化情境**：10×10 網格（面積恰為 100）、
  一個大矩形 + 30 個小矩形（面積恰為大矩形面積）；
- **Python ↔ C++ 對拍**：147 組輸入（含 22 個邊界：空輸入、n 越界、
  座標超界、退化矩形、輸入截斷、負座標……），
  stdin/stdout 字節級一致。

## 應用場景（Applications）

- **地圖 / GIS 覆蓋分析**：多個行政區、地塊、保護區的聯集面積，
  是選址分析（site selection）的基本運算；
- **資料中心機櫃佔地**：把機櫃視為矩形，求機房內被機櫃佔用的總面積；
- **建築物輪廓**：多棟建物平面圖的聯集，估算基地使用率（容積率、覆蓋率）；
- **影像處理 / UI 渲染**：多個有透明重疊的圖層合成後的實際覆蓋像素數；
- **碰撞與覆蓋檢測**：機械臂多臂在平面上的作業區域聯集；
- **廣告位出租**：一塊版面被多個廣告區塊佔用時的可售面積。
