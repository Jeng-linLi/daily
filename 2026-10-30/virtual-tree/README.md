# 虛擬樹（Virtual Tree）：把 O(n) 的原樹壓縮成 O(k) 的小樹

`solution.py`（Python 3 標準庫）與 `solution.cpp`（C++17）行為完全一致：
有 stdin 走 IO 模式，沒有 stdin 就跑內置斷言並輸出 `all tests passed`。

---

## 題意

給定一棵有 n 個節點的根樹（根為 1），節點 u 有權重 `w[u]`。
有 m 次詢問，每次詢問給出 k 個「關鍵節點」（key nodes），
要對這 k 個關鍵節點建立**虛擬樹**並回答：

1. 虛擬樹共有幾個節點；
2. 虛擬樹所有邊的長度總和（邊長 = 原樹上兩端點的距離）；
3. 對每個關鍵節點 u（依節點編號遞增輸出）：
   - `cnt` = 位於 u 的**虛擬樹子樹**中的關鍵節點個數；
   - `sum` = 位於 u 的虛擬樹子樹中的關鍵節點的**權重總和**。

限制：`1 ≤ n ≤ 100000`，`0 ≤ m ≤ 100000`，`0 ≤ k ≤ n`，`|w[u]| ≤ 10^9`。

## 輸入格式

```
n
w_1 w_2 ... w_n
p_2 p_3 ... p_n        （p_u 為 u 的父親，必須 1 ≤ p_u < u）
m
k
k_1 k_2 ... k_k        （k 個互異的關鍵節點）
...（共 m 組）
```

## 輸出格式

每次詢問一行：

```
節點數 邊長總和 cnt_1 sum_1 cnt_2 sum_2 ...
```

其中 `cnt_i, sum_i` 對應**依編號遞增**的第 i 個關鍵節點。
任何結構性錯誤（n 越界、權重超界、父親編號非法、關鍵節點重複或越界、
非整數）輸出 `error`。

## 輸入輸出示例

輸入：

```
6
10 20 30 40 50 60
1 1 2 2 3
3
2
4 5
2
3 6
4
1 4 5 6
```

輸出：

```
3 2 1 40 1 50
2 1 2 90 1 60
5 5 4 160 1 40 1 50 1 60
```

驗算（樹形：1 的兒子是 2、3；2 的兒子是 4、5；3 的兒子是 6）：

- 第一次詢問 `{4, 5}`：兩者的 LCA 是 2，虛擬樹為 `2 - 4`、`2 - 5`，
  共 3 個節點，邊長 1 + 1 = 2；節點 4、5 各自的虛擬子樹裡只有自己。
- 第二次詢問 `{3, 6}`：6 是 3 的兒子，虛擬樹就是原來的那條邊，
  共 2 個節點，邊長 1；節點 3 的虛擬子樹含 `{3, 6}`，cnt = 2、sum = 90。
- 第三次詢問 `{1, 4, 5, 6}`：V = {1, 2, 4, 5, 6}，共 5 個節點，
  邊長 1 + 1 + 1 + 2 = 5；節點 1 的虛擬子樹含全部 4 個關鍵節點，
  cnt = 4、sum = 160。

## 思路

### 1. 為什麼需要虛擬樹

原樹有 n 個節點，但每次詢問只關心 k 個關鍵節點（k ≪ n）。
若每次都在原樹上做一次 DFS，複雜度是 `O(nm)`，完全不可行。
虛擬樹的想法是：**只保留 k 個關鍵節點，以及它們彼此的 LCA**，
把中間沒有關鍵節點的部分壓縮成一條邊。壓縮後的樹最多 `2k − 1` 個節點。

### 2. 虛擬樹的節點集合

令 `V = {關鍵節點} ∪ {LCA(相鄰的兩個關鍵節點)}`。
這裡「相鄰」指的是把關鍵節點依 **DFS 序**排序後相鄰的那一對。

> **定理**：這 k − 1 個 LCA 恰好涵蓋了所有需要的內部節點。
> 因為一個節點若是兩個關鍵節點的 LCA，那麼在 DFS 序上它們之間
> 必然存在一對「相鄰且分居兩側」的關鍵節點。

所以 `|V| ≤ 2k − 1`，虛擬樹的規模只跟關鍵節點數量有關。

### 3. 建構虛擬樹

把 V 依 DFS 序排序，用一個堆疊線性建樹：

- 對每個節點 v，把堆疊頂端「不是 v 的祖先」的節點彈掉；
- 剩下的堆疊頂就是 v 在虛擬樹上的父親。

因為 V 已依 DFS 序排序，任何時刻堆疊中的節點都是一條祖先鏈，
所以這個貪心是對的。邊長 = `depth[child] − depth[parent]`。

### 4. 樹上統計

虛擬樹建好後，`cnt / sum` 就是普通的樹上 DP：
先把關鍵節點的自身權重放進去，再由子往父累加。
因為虛擬樹的節點依 DFS 序排序時「父一定排在子前面」，
**倒序掃描一次**即可完成累加，不需要另外做 DFS。

### 5. 為什麼 cnt / sum 跟原樹子樹的答案一樣

虛擬樹保留了關鍵節點之間的祖先關係：若 u 是 v 的祖先
（u、v 都是關鍵節點），則 u 在虛擬樹上依然是 v 的祖先。
所以「u 的虛擬樹子樹中的關鍵節點」與「u 的原樹子樹中的關鍵節點」
是同一個集合 —— 這正是虛擬樹能加速「多次少量查詢」的關鍵。

### 6. LCA 的查詢

用**倍增表**（binary lifting）求 LCA：
`up[j][v]` 表示 v 的 `2^j` 級祖先，
預處理 `O(n log n)`，單次查詢 `O(log n)`。
祖先判定則用 DFS 序：`u 是 v 的祖先 ⟺ tin[u] ≤ tin[v] < tout[u]`。

## 複雜度

| 項目 | 複雜度 |
|---|---|
| 預處理（LCA 倍增表 + DFS 序） | 時間 O(n log n)，空間 O(n log n) |
| 單次詢問 | O(k log k + k log n) |
| 總計 | O((n + Σk) log n) |
| 暴力參考實作（對拍用） | O(k²) |

## 驗證方式

- **固定用例**：兄弟節點、祖先與後代、跨分支、四個關鍵節點、空詢問、
  負權重鏈 —— 每個都手算驗算過；
- **隨機對拍**：220 組，與 O(k²) 暴力實作（對所有兩兩 LCA 取集合、
  找最深祖先當虛擬父親）逐項比對；
- **深鏈壓力**：n = 5000 的鏈狀樹，驗證迭代 DFS 不爆堆；
- **Python ↔ C++ 對拍**：413 組輸入（含 13 個邊界：空輸入、n = 0、
  父親非法、非整數 token、權重超界、關鍵節點重複……），
  stdin/stdout 字節級一致。

## 應用場景

- **樹上批量路徑查詢**：把 O(n) 的一次遍歷壓縮成 O(k)，
  是「多次少量查詢」的標準加速手段；
- **靜態 LCA 問題**：ZJOI / SNOI 一類「接近的祖先」類題目的核心做法；
- **集合運算型子樹查詢**：合併子集合、統計子樹內不同元素的個數；
- **樹形 DP 的壓縮樹技巧**：換根 DP、依賴子樹大小的 DP 常靠虛擬樹降複雜度；
- **莫隊 + 樹上啟發式合併的基礎設施**：先把詢問點壓成小樹再處理。
