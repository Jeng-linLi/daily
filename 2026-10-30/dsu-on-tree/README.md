# 樹上啟發式合併（DSU on Tree / Sack）：O(n log n) 做子樹顏色統計

`solution.py`（Python 3 標準庫）與 `solution.cpp`（C++17）行為完全一致：
有 stdin 走 IO 模式，沒有 stdin 就跑內置斷言並輸出 `all tests passed`。

---

## 題意

給定一棵有 n 個節點的根樹（根為 1），節點 u 有顏色 `c[u]`（`1 ≤ c[u] ≤ n`）。
有 q 個詢問，每個詢問給出一對 `(u, f)`，要求回答 u 的**子樹**中：

- `distinct` —— 出現過的顏色數；
- `eq` —— 出現次數**恰好等於 f** 的顏色數；
- `shared` —— 出現過、而且在 u 的子樹**之外**也出現過的顏色數。

限制：`1 ≤ n, q ≤ 100000`，`0 ≤ f ≤ n`。

## 輸入格式

```
n
c_1 c_2 ... c_n
p_2 p_3 ... p_n        （p_u 為 u 的父親，必須 1 ≤ p_u < u）
q
u_1 f_1
u_2 f_2
...
```

## 輸出格式

每次詢問一行：

```
distinct eq shared
```

任何結構性錯誤（n 或 q 越界、顏色越界、父親編號非法、詢問節點或 f 越界、
非整數）輸出 `error`。

## 輸入輸出示例

輸入（樹：1 的兒子是 2、3；2 的兒子是 4；3 的兒子是 5、6；
顏色：1, 2, 1, 3, 1, 1）：

```
6
1 2 1 3 1 1
1 1 2 3 3
4
1 1
3 1
3 0
5 1
```

輸出：

```
3 2 0
1 0 1
1 2 1
1 1 1
```

驗算（整棵樹：顏色 1 出現 4 次、2 出現 1 次、3 出現 1 次）：

- `(1, 1)`：整棵樹有 3 種顏色；恰好出現 1 次的顏色是 2、3（2 種）；
  每種顏色的總數都在子樹內，沒有「子樹外也出現」的顏色 → `3 2 0`。
- `(3, 1)`：節點 3 的子樹是 `{3, 5, 6}`，顏色 1 出現 3 次 →
  distinct = 1、f = 1 的顏色數 = 0；顏色 1 全樹共 4 次、子樹內 3 次，
  子樹外也出現 → shared = 1 → `1 0 1`。
- `(3, 0)`：f = 0 的退化定義是「整棵樹出現過、但沒出現在這個子樹裡」的顏色數
  = 3 − 1 = 2 → `1 2 1`。
- `(5, 1)`：葉節點 5，顏色 1；distinct = 1、f = 1 的顏色數 = 1；
  顏色 1 在子樹外也出現 → `1 1 1`。

## 思路

### 1. 為什麼需要這招

樸素做法是對每個節點 u 單獨遍歷一次子樹，O(n²)。
「樹上啟發式合併」（又稱 DSU on Tree / Sack / 同步 bags）
藉由**重輕劃分**把總複雜度降到 O(n log n)。

### 2. 重輕劃分（heavy-light by subtree size）

對每個節點 u，取子樹最大的那個兒子當「重兒子」（heavy child），
其餘都是「輕兒子」（light child）。

> **關鍵性質**：從根往下走，**輕邊最多只有 O(log n) 條** ——
> 因為走過一條輕邊 (u, v) 時 `size[v] ≤ size[u] / 2`，
> 子樹大小每走一條輕邊就至少減半，所以輕邊數是 O(log n)。

### 3. Sack 的流程

維護一個「全域狀態」（bag），記錄目前被加入的節點的顏色統計。
對節點 u 的處理分成三段：

| 段 | 動作 |
|---|---|
| (a) | 先處理所有**輕兒子**，處理完立刻清空它們的貢獻（`keep = false`） |
| (b) | 再處理**重兒子**，但**保留**它的貢獻（`keep = true`） |
| (c) | 把所有輕兒子的子樹重新加回來，再加上 u 自己 —— 此刻 bag 恰好就是 u 的子樹，據此回答 u 的詢問 |
| (d) | 若 `keep = false`，把 u 的整個子樹移出 bag |

輕兒子的貢獻被加入又移除了兩次、重兒子只加入一次，
而每個節點只會是它祖先的 O(log n) 個輕兒子之一，
所以總加入次數是 **O(n log n)**。

> **不變式**：每次進入 `dfs(u, ·)` 時 bag 都是空的，
> 而 `dfs(u, true)` 返回時 bag 恰好是 u 的子樹。
> 所以 (c) 段之後 bag = u 的子樹，可以直接回答 u 的詢問。

實作上用**迭代 DFS**（stack 模擬 stage 0 / stage 1），避免深鏈造成
Python 遞迴爆堆；「把輕兒子整棵加回來」則靠 DFS 序的性質完成 ——
先序序列中 u 的子樹恰好佔據連續區間 `[tin[u], tin[u] + size[u])`。

### 4. 維護哪些統計量

| 變數 | 意義 |
|---|---|
| `cnt[c]` | 顏色 c 在 bag 中的出現次數 |
| `freq[f]` | 出現次數恰好為 f 的顏色數（f ≥ 0） |
| `distinct` | 出現過的顏色數 |
| `shared` | 出現過、且在子樹之外也出現過的顏色數 |
| `total[c]` | 顏色 c 在整棵樹中的總出現次數（一次預處理） |
| `palette` | 整棵樹用到的不同顏色數 |

加入一個顏色 c（`cnt` 從 a 變成 a+1）：

- `freq[a] -= 1`；`freq[a+1] += 1`
- `distinct`：a == 0 時 +1
- `shared`：判斷 `(0 < cnt[c] < total[c])` 在變化前後是否成立，
  成立狀態改變就相應 +1 / −1

移出一個顏色 c 完全對稱。於是每次加入 / 移出都是 **O(1)**。

### 5. 顏色的「宇宙」與 f = 0 的退化定義

顏色的宇宙取整棵樹用到的 `palette` 種顏色，
因此 `freq[0]` 初始值 = `palette`，`eq(0) = freq[0] = palette − distinct`
（也就是「在整棵樹出現過、但沒出現在這個子樹裡」的顏色數），
與 `shared` 的語意保持一致。

### 6. 為什麼不問「最多的顏色」

常見的「子樹內最多的顏色」需要維護 max frequency，
但在 Sack 裡移除是「整批移除子樹」，max 會難以 O(1) 修正。
本題改問「恰好 f 次的顏色數」，用 `freq[]` 陣列即可 O(1) 回答，
避開了 max 追蹤的陷阱。

## 複雜度

| 項目 | 複雜度 |
|---|---|
| 預處理（DFS 序、子樹大小、重輕劃分、顏色總數） | 時間 O(n) |
| 單次詢問 | O(1)（在 DFS 到 u 的當下直接算） |
| 總計 | O(n log n + q) |
| 空間 | O(n) |

## 驗證方式

- **固定用例**：6 個節點的手算樹，13 筆詢問全部逐一手算驗證；
  另有單節點樹、所有節點同色兩組退化情境；
- **隨機對拍**：120 組小樹 + 10 組中大型樹（每個節點都問），
  與「對每個詢問單獨遍歷子樹」的 O(nq) 暴力實作逐項比對；
- **深鏈壓力**：n = 4000 的鏈狀樹，驗證迭代實作不爆堆；
- **Python ↔ C++ 對拍**：205 組輸入（含 27 個邊界：空輸入、n/q 越界、
  顏色與 f 越界、父親非法、非整數 token、輸入截斷……），
  stdin/stdout 字節級一致。

## 應用場景

- **專案目錄的檔案副檔名統計**：每個子目錄有多少種副檔名、
  有多少副檔名只出現一次、哪些副檔名與其他目錄共用；
- **基因組 / 蛋白質序列的子樹特徵統計**：以葉節點為 k-mer 的系統發育樹；
- **程式碼倉庫的語言分布分析**：每個資料夾用了幾種語言、
  哪些語言只在單一資料夾出現（協助決定統一 formatting 工具）；
- **線上統計「某個資料夾內有多少種唯一的檔案類型」**：
  清理重複檔案的決策依據；
- **競賽常青題**：CF 600E「Lomsat gelrel」、CF 375D「Tree and Queries」
  一類子樹統計題的核心手法。
