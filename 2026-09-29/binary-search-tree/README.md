# 二元搜尋樹（BST）：插入 / 搜尋 / 刪除 / 中序遍歷

| 項目 | 內容 |
|---|---|
| 主題 | 樹 · 二元搜尋樹 |
| 語言 | Python 3（`solution.py`）/ C++17（`solution.cpp`） |
| 核心考點 | BST 不變量、中序遍歷有序性、刪除的三種情形（中序後繼頂替）、退化成鏈的風險 |
| 複雜度 | 插入 / 搜尋 / 刪除 均爲 O(h)，h 爲樹高（平衡時 O(log n)，退化時 O(n)）；中序遍歷 O(n)，空間 O(h) |

## 題意

先給出 `n` 個待插入的鍵值，再給出 `m` 個待刪除的鍵值，維護一棵二元搜尋樹並依次輸出：

1. 全部插入後的中序遍歷（非嚴格升序）；
2. 全部插入後的樹高（空樹爲 0，只有根節點時爲 1）；
3. 在插入後的樹上依次搜尋這 `m` 個鍵值的結果（找到 1、否則 0）；
4. 依次刪除這 `m` 個鍵值（每個鍵值只刪掉一個副本，不存在則忽略）後的中序遍歷；
5. 刪除完成後的樹高。

重複鍵值的約定：插入時「大於等於」當前節點值的走右子樹，因此中序遍歷是非嚴格升序。

## 思路

BST 的核心不變量：對任意節點 x，**左子樹所有鍵值 < x.val <= 右子樹所有鍵值**。
有了它，搜尋就退化成二分 —— 每次比較都能排除掉一棵子樹，插入 / 搜尋 / 刪除都只沿著
一條從根到葉的路徑走，複雜度 O(h)。

> ⚠️ 樸素 BST **不做平衡**，有序插入時會退化成一條鏈（h = n），操作退化成 O(n)。
> 這也是爲什麼工程上要用 AVL / 紅黑樹 / Treap 這類自平衡結構。

刪除是最麻煩的一步，分三種情形：

| 情形 | 做法 |
|---|---|
| 葉子節點 | 直接摘掉 |
| 只有一棵子樹 | 讓那棵子樹頂替它的位置 |
| 左右子樹都在 | 找**中序後繼**（右子樹中的最小節點），把它的值搬到當前節點，再刪掉那個後繼 |

第三種情形不能直接摘掉節點，否則兩棵子樹會一起丟失。中序後繼是「比當前值大的最小者」，
把它搬上來不會破壞 BST 不變量；而後繼節點至多只有右孩子，所以第二趟刪除必定落在
前兩種簡單情形。（用中序前驅、即左子樹的最大節點，同理可行。）

實作細節：本題的插入 / 刪除 / 遍歷 / 求高全部寫成**迭代**版本 —— 一是避免樹退化成鏈時
Python 遞迴爆棧，二是刪除時用一個棧上的「哨兵父節點」可以讓刪根節點不用特判。

## 複雜度

| 操作 | 時間 | 空間 |
|---|---|---|
| 插入 / 搜尋 / 刪除 | O(h) | O(1) |
| 中序遍歷 / 求高 / 計數 / 合法性檢查 | O(n) | O(h)（顯式棧） |

## 輸入輸出

輸入（空白分隔即可）：

```
n m
a1 a2 ... an        # 依次插入；n = 0 時這行省略
b1 b2 ... bm        # 依次刪除；m = 0 時這行省略
```

輸出：

```
第 1 行：插入後的中序遍歷，空格分隔（空樹輸出空行）
第 2 行：插入後的樹高
第 3 行：m 個鍵值的搜尋結果（1/0），空格分隔
第 4 行：刪除後的中序遍歷
第 5 行：刪除後的樹高
```

### 示例

輸入：

```
5 2
5 3 7 3 6
3 7
```

輸出：

```
3 3 5 6 7
3
1 1
3 5 6
2
```

解釋：插入 `[5,3,7,3,6]` 後中序爲 `[3,3,5,6,7]`（重複鍵值都在），樹高 3；
兩個待刪鍵值都存在（輸出 `1 1`）；刪掉一個 3 和一個 7 之後剩下 `[3,5,6]`，樹高 2。

## 怎麼跑

```bash
python solution.py          # 無 stdin：跑內置斷言測試，輸出 all tests passed

echo "5 2
5 3 7 3 6

```

## 應用場景

- **字典 / 索引**：`std::map`、資料庫 B+ 樹索引的底層思想都是「有序 + 二分下降」；
- **區間查詢與排名**：給每個節點維護子樹大小，就能 O(h) 求「第 k 小」和「某值的排名」；
- **記憶**：BST 的中序遍歷 = 升序輸出，這是判斷一棵樹是否爲 BST 最常用的切入點。
