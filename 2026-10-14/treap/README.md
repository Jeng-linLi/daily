# 隨機 Treap：旋轉版 / FHQ（split-merge）版 / 隱式 Treap 區間翻轉

`solution.py`（Python 3 標準庫）・`solution.cpp`（C++17）

## 題意

維護一棵以 `key` 為序的平衡二元搜尋樹，支援：

| 操作 | 說明 |
|---|---|
| `insert(x)` | 插入 `x`（允許重複） |
| `erase(x)` | 刪除一個 `x`（不存在則無動作） |
| `contains(x)` | 是否存在 |
| `kth(k)` | 第 `k` 小（1-indexed），越界回傳 `-1` |
| `rank(x)` | 嚴格小於 `x` 的元素個數 |
| 中序遍歷 | 輸出排序後的序列 |

另外用**隱式 Treap** 維護初始序列，支援區間翻轉 `[l, r]`。

題目同時用「旋轉版」與「FHQ 版」兩套實作做同一件事並互相對拍，最後輸出一個旗標表示
「兩版中序一致、且 BST 性質與堆性質都成立」。

## 思路

### Treap = Binary Search Tree + Heap

每個節點帶兩個權值：

- `key` 滿足 **BST 性質**：左子樹 < 自己 ≤ 右子樹；
- `prio` 滿足 **堆性質**（本題用小根堆）：父節點的 `prio` 小於兩個兒子。

若 `prio` 是隨機獨立均勻的，則「`key` 決定的 BST 形狀」恰好等價於「按 `prio` 由小到大插入的順序」，
也就是一棵**隨機 BST**，期望深度 `O(log n)`。這正是 Treap 不需要像 AVL / 紅黑樹那樣
維護平衡資訊的原因：**隨機性本身就是平衡**。

### 旋轉版：插入後靠旋轉把 prio 提上去

先按普通 BST 規則遞迴插到底，回程時若「兒子的 `prio` 比自己小」就旋轉：

- 左兒子 `prio` 更小 → 右旋（zig）
- 右兒子 `prio` 更小 → 左旋（zag）

旋轉只改變父子關係、不破壞中序序列，所以是合法的平衡化手段。

刪除則是「把目標節點旋轉到葉子再丟棄」：
只有一個兒子就讓兒子頂替；兩個都在就把 `prio` 較小的那個兒子旋轉上來，再往另一側繼續刪。

### FHQ Treap：只用 split 與 merge

FHQ（范浩強）Treap 完全不寫旋轉，只靠兩個操作：

```
merge(a, b)   # 要求 a 的所有 key ≤ b 的所有 key；prio 小者當根，遞迴合併另一側
split(t, key) # 切成 (所有 key ≤ key, 所有 key > key)
```

於是

```
insert(x) = split(t, x) → merge(A, new) → merge(..., B)
erase(x)  = split(t, x) → split(A, x-1) → 丟掉中間那一棵的一個節點
```

FHQ 的優勢是結構持久化友善、區間操作直觀，而且天然支援隱式 Treap。

### 隱式 Treap：用「下標」當 key

把序列第 `i` 個元素放在「中序遍歷第 `i` 個位置」的節點上，不需要真的存 `key`，
只維護子樹大小 `sz`：

- `split_size(t, k)` 切成「前 `k` 個」與「剩下的」
- 區間翻轉 `[l, r]` = 切出三段 → 給中段打懶標記 → 合併回去

懶標記 `rev` 用 XOR 下傳（`push`）：打兩次等於沒打，這正好就是翻轉的語義。

### 為什麼兩個語言能逐位元組一致

Treap 的形狀完全由 `prio` 序列決定。本題用 **xorshift64** 確定性亂數（種子固定），
而且「隱式 Treap / FHQ 版 / 旋轉版」各自用**獨立的亂數流**，
因此 Python 與 C++ 構造出的樹完全同構，輸出必然一致。

## 複雜度（期望值）

| 操作 | 複雜度 |
|---|---|
| 插入 / 刪除 / 查詢 / 第 k 小 / 排名 | `O(log n)` |
| 隱式 Treap 區間翻轉 | `O(log n)`（懶標記 `O(1)`） |
| 中序遍歷 | `O(n)` |
| 空間 | `O(n)` |

## 輸入格式

```
n                      初始序列長度（隱式 Treap 的內容）
v_1 ... v_n            初始序列
q                      操作數
op a b                 q 組，每組 3 個整數
```

| `op` | 含義 |
|---|---|
| `1 x 0` | `insert(x)` |
| `2 x 0` | `erase(x)` |
| `3 x 0` | `contains(x)` → 輸出 `1 / 0` |
| `4 k 0` | `kth(k)`（1-indexed）→ 輸出值，越界 `-1` |
| `5 x 0` | `rank(x)` → 輸出嚴格小於 `x` 的個數 |
| `6 l r` | 隱式 Treap 翻轉 `[l, r]`（1-indexed 閉區間） |

非數字 token 一律視為「輸入到此為止」；讀不滿的那一組直接丟棄。
`n`、`q` 截斷到 `[0, 5000]`；數值截斷到 `[-10^12, 10^12]`。

## 輸出格式（5 行）

```
BST 元素個數
中序遍歷（空格分隔；空則為空行）
op = 3 / 4 / 5 的查詢結果（依執行順序，空格分隔）
隱式 Treap 最終序列（空格分隔）
1 = 兩版一致且性質成立
```

## 範例

輸入：

```
5
5 4 3 2 1
8
1 3 0
1 1 0
1 7 0
3 7 0
4 2 0
5 3 0
2 7 0
6 2 4
```

輸出：

```
2
1 3
1 3 1
5 2 3 4 1
1
```

解讀：插入 `3, 1, 7` 後 `contains(7)=1`、`kth(2)=3`、`rank(3)=1`（只有 `1` 比它小）；
刪除 `7` 後 BST 剩 `{1, 3}`；序列 `[5,4,3,2,1]` 翻轉 `[2,4]` 得 `[5,2,3,4,1]`。

## 怎麼跑

```bash
python solution.py          # 無 stdin → 跑內置斷言，輸出 all tests passed
g++ -std=c++17 -O2 -Wall solution.cpp -o solution && ./solution
```

> Windows / MinGW 下不要把編譯產物輸出到 `/tmp`（鏈接器會報 No such file or directory）。

## 應用場景

- 想要平衡樹但不想寫紅黑樹：資料庫索引、記憶體 KV 儲存的排序結構
- 隱式 Treap 是「可持久化序列」與「區間操作」的基礎：文字編輯器的行緩衝、區間翻轉 / 區間移動
- `split` / `merge` 的語義讓 Treap 很容易改成**持久化 Treap**（函數式資料結構）
- 競賽：普通平衡樹（插入 / 刪除 / 排名 / 前驅後繼）、序列維護（文藝平衡樹）
