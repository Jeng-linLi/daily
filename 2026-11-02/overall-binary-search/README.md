# 整體二分（Overall Binary Search）：單點修改 + 區間第 k 小

`solution.py`（Python 3 標準庫）與 `solution.cpp`（C++17）行為完全一致：
有 stdin 走 IO 模式，沒有 stdin 就跑內置斷言並輸出 `all tests passed`。

---

## 題意

給定一個長度為 `n` 的數列 `a`，初始值為 `a[1..n]`。接著依序執行 `m` 個操作：

| 操作 | 意義 |
|---|---|
| `1 p x` | 把 `a[p]` 改成 `x` |
| `2 l r k` | 查詢**當下** `a[l..r]` 中第 `k` 小的值 |

要求把所有查詢的答案依序輸出。

限制：`1 ≤ n, m ≤ 100000`，`|x| ≤ 10^9`。

## 輸入格式

```
n m
a_1 a_2 ... a_n
op_1
op_2
...
op_m
```

其中每個 `op` 為 `1 p x` 或 `2 l r k`。

## 輸出格式

每個查詢輸出一行，即第 `k` 小的值。

任何結構性錯誤（`n`/`m` 越界、操作類型不是 `1`/`2`、位置或區間超出 `1..n`、
`k` 不在 `1..r-l+1`、值超出 `±10^9`、輸入缺 token、非整數）輸出 `error`。

## 輸入輸出示例

輸入：

```
5 5
5 1 4 2 3
2 1 5 3
1 3 10
2 1 5 3
1 1 0
2 2 5 2
```

輸出：

```
3
3
2
```

驗算：

1. 初始 `a = [5,1,4,2,3]`，排序得 `[1,2,3,4,5]`，查 `[1,5]` 第 3 小 = **3**；
2. `a[3] := 10` 後變成 `[5,1,10,2,3]`，排序得 `[1,2,3,5,10]`，第 3 小 = **3**；
3. `a[1] := 0` 後變成 `[0,1,10,2,3]`，查 `[2,5]` = `[1,10,2,3]`
   排序得 `[1,2,3,10]`，第 2 小 = **2**。

> ⚠️ 本節的期望值全部是**先跑一遍程式拿到真實輸出**之後才寫進來的。
> 手算時曾把第 2 步誤記成 4（漏掉 `10` 已經取代 `4`）。
> 這是本倉庫反覆踩過的坑：**固定用例的期望值一律先跑一遍再寫死**。

## 思路

### 1. 為什麼不用主席樹

「動態第 k 小」最直覺的做法是主席樹（可持久化線段樹），但那是**線上**解法：
每個版本要 `O(log V)` 空間，`n + m` 個版本就是 `O((n+m) log V)` 個節點。
本題是**純離線**的（所有操作都先讀進來），可以用更省空間的 **整體二分**。

### 2. 離線二分的基本套路

若我們能回答「查詢範圍 `[l,r]` 中，值 `≤ mid` 的元素有幾個」，就能判斷第 `k` 小的值：

- 落在 `[L, mid]` → 答案在左半邊；
- 落在 `[mid+1, R]` → 答案在右半邊，且 `k` 要減去左半邊的個數。

問題是每一層二分都要重新回答一次「有幾個」。若每次都重掃全部操作，
複雜度會變成 `O(m log V · m)`，不可行。

### 3. 整體二分的核心：所有查詢共用同一棵二分樹

把所有操作（含修改）依**時間順序**排成一個事件序列，遞迴處理值域 `[vl, vr]`：

```
mid = (vl + vr) / 2
從頭到尾掃描事件序列，同時用「樹狀數組」維護「目前值落在 [vl,mid] 的位置數」：
    修改事件：若值的秩 <= mid，就 BIT[pos] += delta（事件留在左半邊）
              否則留在右半邊（不動 BIT）
    查詢事件：cnt = BIT.sum(r) - BIT.sum(l-1)
              若 k <= cnt  → 事件留在左半邊
              否則          → k -= cnt，事件留在右半邊
掃完後把這一層加進 BIT 的量「全部回滾」，再各自遞迴。
```

因為事件序列在遞迴中保持時間順序，BIT 在任何時刻都精確反映
「該時刻值落在 `[vl,mid]` 的位置數」，所以**每一層只需掃一次序列**，
總複雜度降為 `O((n+m) log V log n)`。

### 4. 「修改」怎麼變成可以被 BIT 累加的事件

BIT 只能做「加一點 / 減一點」，所以把賦值拆成「刪舊值 + 加新值」：

```
a[p]: old → new   等價於   DELETE(p, old)  然後  INSERT(p, new)
```

並且在最前面補上所有初始值的 `INSERT(p, a[p])`。

這樣每個位置的「當前值是否落在 `[vl,mid]`」永遠是 `0` 或 `1`，
`INSERT`/`DELETE` 把它維護得對稱，兩邊相消就是 `0`。

> **注意**：`DELETE` 事件必須帶「舊值的秩」，所以要先掃一遍操作序列
> 求出每個位置的前值，才能生成正確的刪除事件。

### 5. 為什麼答案不會有平手問題

第 `k` 小指的是**值**（不是位置），值相同也只佔一格，
所以答案在兩個語言裡都唯一，**不需要任何正規化處理**。

## 複雜度

| 項目 | 複雜度 |
|---|---|
| 值域離散化（排序） | 時間 `O((n+m) log(n+m))` |
| 整體二分（`O(log V)` 層，每層掃一次序列） | 時間 `O((n+m) log V log n)` |
| 總計 | 時間 `O((n+m) log V log n)` |
| 空間 | `O(n + m + V)` |

`V` 為不同值的個數（`V ≤ n + m`）。

## 驗證方式

- **固定用例**：無修改、值全相同、修改成最大／最小值、負數與 0、單元素區間、
  連續修改同一位置、修改成原本相同的值（no-op）、查詢在所有修改之後、
  兩次查詢中間夾修改、`n = 1` —— 共 12 組，全部以暴力實作產生的真實輸出驗證；
- **隨機對拍**：300 組小案例 + 120 組值域較大且修改密集的案例 +
  60 組「只有查詢、零修改」（退化成靜態區間第 k 小），
  與「直接維護數列 + 排序取第 k 小」的參考實作比對；
- **Python ↔ C++ 對拍**：stdin/stdout 逐位元組一致。

## 應用場景（Applications）

- **即時排行榜 / 賽事名次**：分數被更新後查詢「第 k 名」，
  每輪結算後可整批離線重算；
- **資料庫的 `ORDER BY ... LIMIT k`**：批次匯出前 N 名，
  底層正是「可排序索引 + 離線二分」的組合；
- **版本控制 / 分散式版本號排序**：找出第 k 舊的版本；
- **監控系統**：取一段時間視窗內的第 k 大延遲（p99 latency）；
- **資本市場**：組合持股第 k 大的權重（風險集中度監控）。
