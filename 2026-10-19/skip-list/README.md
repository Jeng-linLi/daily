# 跳表（Skip List）

`solution.py`（Python 3 標準庫）與 `solution.cpp`（C++17）行為完全一致：
有 stdin 走 IO 模式，沒有 stdin 就跑內置斷言並輸出 `all tests passed`。

---

## 題意

維護一個**有序多重集合**（允許重複元素），支援七種操作，並與「有序陣列 + 二分」
的參考實作逐項對拍，確保跳表的每一個答案都正確。

| 操作碼 | 名稱 | 說明 |
|---|---|---|
| 1 | `insert x` | 插入 x（允許重複） |
| 2 | `erase x` | 刪除一個 x，不存在則忽略 |
| 3 | `count x` | x 的出現次數 |
| 4 | `rank x` | 嚴格小於 x 的元素個數 |
| 5 | `kth k` | 第 k 小的元素（k 從 1 起算），越界回傳 -1 |
| 6 | `pred x` | 嚴格小於 x 的最大元素，不存在回傳 -1 |
| 7 | `succ x` | 嚴格大於 x 的最小元素，不存在回傳 -1 |

## 輸入格式

```
q                    操作數（0 ≤ q ≤ 300；負數視為 0）
op x                 q 行，每行一個操作
```

全部 token 以空白分隔；遇到非整數 token 就當成「輸入到此為止」，缺值補預設。
`op` 不在 1..7 的操作直接忽略；`x` 會被夾到 `[0, 10^6]`
（這樣 `-1` 才能安全地當作「不存在」的哨兵）。

## 輸出格式（共 3 行）

```
第 1 行：所有查詢（op ≥ 3）的結果，以空格分隔；沒有查詢就是空行
第 2 行：size 以及排序後的全部元素，以空格分隔
第 3 行：ok 旗標（1 = 跳表與有序陣列參考實作完全一致）
```

## 輸入輸出示例

輸入：

```
10
1 5
1 3
1 7
3 3
4 5
5 2
6 4
7 4
2 3
5 1
```

輸出：

```
1 1 5 3 5 5
2 5 7
1
```

逐步解釋：

| 步驟 | 集合 | 結果 |
|---|---|---|
| insert 5 / 3 / 7 | {3, 5, 7} | — |
| count 3 | | 1 |
| rank 5 | | 1（只有 3 比 5 小） |
| kth 2 | | 5 |
| pred 4 | | 3 |
| succ 4 | | 5 |
| erase 3 | {5, 7} | — |
| kth 1 | | 5 |

最終 `size = 2`，排序後 `[5, 7]`。

邊界輸入：

```
輸入 "" →  輸出 "\n0\n1\n"      （空集合：沒有查詢、size 0）
輸入 "0" → 輸出 "\n0\n1\n"
```

## 思路

### 1. 為什麼需要跳表

有序陣列的插入 / 刪除是 O(n)；平衡樹（紅黑樹、AVL）能做到 O(log n)，但旋轉規則複雜、
併發環境下難以細粒度加鎖。跳表用「**機率平衡**」換來簡潔：

- 每個節點隨機一個層高 `lv`，滿足 `P(lv ≥ k) = 2^{-(k-1)}`；
- 第 i 層的指標串起一條「稀疏高速公路」，越高層跳過越多節點；
- 搜尋時從最高層往右走，走不過去就下降一層，期望步數 O(log n)。

不需要旋轉、不需要重新平衡，插入刪除只是「改幾個指標」。

### 2. span（跨度）欄位：讓排名也能 O(log n)

純指標只能回答「在不在」。要回答 `rank` / `kth`，必須知道每條邊**跨過幾個節點**。
所以每個節點在第 i 層額外存 `span[i]`：從自己沿第 i 層指標走一步，等於在第 0 層往前跳幾個節點。

插入一個層高為 `lv` 的節點時：

- `i < lv`：新節點切斷舊邊，兩段跨度分別是 `(rank[0] - rank[i])` 與 `舊跨度 - (rank[0] - rank[i])`
- `i ≥ lv`：舊邊仍然存在，跨度直接 `+1`

刪除則是逆向操作：`update[i].span[i] += x.span[i] - 1`（邊被接上時），否則 `-= 1`。

有了 span：

- `rank(x)` = 沿路累加 span，直到下一個節點的 key ≥ x
- `kth(k)` = 沿路累加 span，只要 `traversed + span ≤ k` 就往前跳
  （第 0 層的 span 恆為 1，所以最後一定停在 `traversed == k`）
- `count(x)` = `count_leq(x) - count_less(x)`
- `pred(x)` = `kth(rank(x))`、`succ(x)` = `kth(count_leq(x) + 1)`

### 3. 隨機層高必須跨語言一致

Python 的 `random` 與 C++ 的 `mt19937` 給出的序列不同，兩邊的「樹形」會長得不一樣。
雖然最終答案應該相同，但對拍時就無法確認內部結構一致。
這裡兩個版本都用**同一組 LCG 常數**自製亂數，取 64 位元的第 33 位當硬幣：

```
state = state * 6364136223846793005 + 1442695040888963407   (mod 2^64)
擲到 1 就停止，否則層高 + 1（上限 32 層）
```

C++ 用 `unsigned long long` 的自然溢位，Python 用 `& (2^64 - 1)`，兩邊逐位元相同。

### 4. 不變量檢查

`validate()` 對每一層的每一條邊，都用第 0 層指標**實際走一趟**，
確認 `span[i]` 等於真實距離。這個檢查是 O(n²)，
但能抓出「跨度算錯、但這組操作碰巧答案對」的 bug。

## 複雜度

| 操作 | 期望時間 | 說明 |
|---|---|---|
| 搜尋 / 插入 / 刪除 | O(log n) | 層高期望 2，每層期望走 2 步 |
| `rank` / `kth` / `pred` / `succ` | O(log n) | 靠 span 欄位，不需要走到底 |
| `count` | O(log n) | `count_leq - count_less` |
| 空間 | O(n) 期望 | 每個節點期望 2 條邊，最壞 O(n log n) |

最壞情況（全部節點都抽到 32 層）退化成 O(n)，但機率是 2^{-31n}。

---

## 應用場景

- **Redis 有序集合（zset）**：底層就是跳表（`zskiplist`），`ZRANK` / `ZRANGE` / `ZSCORE` 全靠 span 欄位
- **LevelDB / RocksDB 的 MemTable**：寫入密集的記憶體索引，跳表比 B-tree 更容易做無鎖讀
- **併發資料結構**：跳表只需要鎖「前驅節點」那幾條邊，比平衡樹的整棵子樹旋轉友善得多
- 排行榜、時間軸、價格檔位這類「有序 + 頻繁插入刪除 + 要查排名」的中介層

## 怎麼跑

```bash
# Python（無 stdin → 跑內置斷言）
python solution.py

# Python（有 stdin → IO 模式）
printf '4\n1 5\n1 3\n3 3\n4 5\n' | python solution.py

# C++
g++ -std=c++17 -O2 solution.cpp -o sl && ./sl
```

> Windows / MinGW 下不要把編譯產物輸出到 `/tmp`（鏈接器會報 No such file or directory），
> 輸出到當前目錄或 `_build/` 即可。
