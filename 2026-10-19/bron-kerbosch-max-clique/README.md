# 最大團與 Bron–Kerbosch 演算法

`solution.py`（Python 3 標準庫）與 `solution.cpp`（C++17）行為完全一致：
有 stdin 走 IO 模式，沒有 stdin 就跑內置斷言並輸出 `all tests passed`。

---

## 題意

給一張 n 點的無向簡單圖（鄰接矩陣），求：

1. **最大團大小**（maximum clique）：最大的「兩兩相鄰」的點集有多大
2. **極大團的數量**（maximal cliques）：不能再加進任何點的團有幾個
3. **字典序最小的那個最大團**的點集合
4. **最大獨立集**（兩兩不相鄰的最大點集）與**最小點覆蓋**
5. 全部結果都與「枚舉 2^n 個子集」的暴力版對拍（n ≤ 14 時）

## 輸入格式

```
n m                  點數與邊數（0 ≤ n ≤ 20，0 ≤ m ≤ 190）
u v                  m 行，每條邊的兩個端點（0 ≤ u, v < n）
```

全部 token 以空白分隔；遇到非整數 token 就當成「輸入到此為止」，缺值補預設。
自環（`u == v`）與越界邊會被直接丟棄；重複邊只算一次。

## 輸出格式（共 5 行）

```
第 1 行：mc1 mc2 mc_bf        最大團大小（樞軸版 / 著色上界版 / 暴力版）
第 2 行：cnt cnt_bf           極大團數量（樞軸版 / 暴力版）
第 3 行：k v1 v2 ... vk       字典序最小的最大團（k = 0 時只有一個 0）
第 4 行：mis mvc mis_bf       最大獨立集 / 最小點覆蓋 / 暴力版獨立集
第 5 行：ok 旗標
```

n > 14 時暴力版不跑，對應欄位輸出 `-1`（空圖的 `mis_bf` 例外，見下）。

## 輸入輸出示例

輸入（兩個三角形 `0-1-2` 與 `3-4-5`，用橋 `2-3` 接起來）：

```
6 7
0 1
0 2
1 2
2 3
3 4
4 5
3 5
```

輸出：

```
3 3 3
3 3
3 0 1 2
2 4 2
1
```

逐步解釋：

| 行 | 值 | 說明 |
|---|---|---|
| 1 | `3 3 3` | 三種算法都算出最大團是 3（`{0,1,2}` 或 `{3,4,5}`） |
| 2 | `3 3` | 極大團恰有 3 個：`{0,1,2}`、`{2,3}`、`{3,4,5}` |
| 3 | `3 0 1 2` | 字典序最小的最大團是 `{0, 1, 2}` |
| 4 | `2 4 2` | 最大獨立集 2（例如 `{0, 4}`），最小點覆蓋 = 6 - 2 = 4 |
| 5 | `1` | 所有對拍通過（含 α + τ = n） |

其他小例子：

```
輸入 "0 0"                   輸入 "3 3\n0 1\n1 2\n0 2"
輸出:                        輸出:
0 0 0                        3 3 3
1 1                          1 1
0                            3 0 1 2
0 0 0                        1 2 1
1                            1

輸入 "3 2\n0 1\n1 2"
輸出:
2 2 2                        ← 路徑 0-1-2，最大團是 2
2 2                          ← 極大團 {0,1} 與 {1,2}
2 0 1                        ← 字典序最小：{0, 1}
2 1 2                        ← 獨立集 {0, 2} 大小 2，點覆蓋 1
1
```

> 空圖（n = 0）的最大團大小是 0，而空集合本身也算一個極大團，所以數量是 1。

## 思路

### 1. Bron–Kerbosch：列舉所有極大團

維護三個集合：

- `R`：目前這條搜尋路徑上已經選進團裡的點
- `P`：還能加進來的候選點（與 R 中所有點都相鄰）
- `X`：已處理過、用來避免重複列舉同一個極大團的點

當 `P` 與 `X` 同時為空，`R` 就是一個**極大團**（加不進任何點了）。

### 2. 樞軸（pivot）剪枝

沒有樞軸的版本會對同一個極大團重複搜尋很多次。
取 `u ∈ P ∪ X` 中「`|P ∩ N(u)|` 最大」的那個當樞軸（平手取編號最小的）：

> 任何極大團要嘛包含 u、要嘛包含某個「與 u 不相鄰」的點。

所以只需遞迴 **`P \ N(u)`** 裡的點，候選數目明顯變小，而且不漏解。

### 3. 貪心著色上界（branch and bound）

只求「大小」不求「列舉」時可以剪得更兇。對候選集合 `P` 做一次貪心著色：
依序給每個點塗上「鄰居沒用過的最小顏色」，得到 `color[v]`。
因為同一個團裡任兩點相鄰，顏色必互不相同，所以

```
|R| + color[v] ≤ 目前最佳解   ⟹   從 v 出發不可能更好，直接剪掉
```

這就是 Tomita 的 MCQ 演算法，實務上比純樞軸版快非常多。

⚠️ **本題開發時踩到的坑**：貪心著色**不保證** `color` 隨下標遞增。
例如三個點 0-1 相鄰、2 孤立時顏色是 `[1, 2, 1]`，此時 `color[2] = 1`
並不是 `{v₀, v₁, v₂}` 的上界。上界必須取**前綴最大值** `max(color[0..i])`，
否則會把還有機會的分支誤剪掉（第一版就因此把 5 算成 4）。
另一種做法是著色後把候選集依顏色排序，讓 `color` 變成單調。

### 4. 最大獨立集 = 補圖的最大團

原圖的獨立集（兩兩**不**相鄰）正好是補圖的團（兩兩相鄰）。
而對任意圖都有 `α + τ = n`（最大獨立集 + 最小點覆蓋 = 點數），
因為點覆蓋的補集一定是獨立集，反之亦然。

程式裡同時驗證這兩件事：補圖的最大團 == 原圖的最大獨立集，且 `mis + mvc == n`。

### 5. 跨語言一致的排序

著色的順序、樞軸的平手規則、遞迴枚舉順序全部寫死成「編號由小到大」。
否則 Python 與 C++ 的集合迭代順序不同，剪枝量就不同，輸出對不起來。

## 複雜度

| 項目 | 時間 | 說明 |
|---|---|---|
| 樞軸版列舉所有極大團 | O(3^{n/3}) | 最壞情況，且這個界是緊的（Moon-Moser 圖） |
| 著色上界版求最大團 | 最壞同階 | 實務上遠快於樞軸版 |
| 補圖求最大獨立集 | 同上 | 再做一次即可 |
| 空間 | O(n²) + O(n) | 鄰接矩陣 + 遞迴深度 |
| 暴力版（n ≤ 14） | O(2^n · n²) | 枚舉所有子集並檢查 |

## 應用場景

- **社群網路**：找出「一群互相認識的人」——clique 就是最緊密的社群結構
- **生物資訊**：蛋白質交互作用網路裡找功能模組；基因共表現聚類
- **編譯器**：暫存器分配時的干涉圖、指令排程的衝突圖（要找的是獨立集）
- **化學資訊學**：用最大團做分子結構比對（兩個分子圖的最大公共子結構）
- **排班 / 會議安排**：獨立集 = 可以同時進行的任務集合

## 怎麼跑

```bash
# Python（無 stdin → 跑內置斷言）
python solution.py

# Python（有 stdin → IO 模式）
printf '3 3\n0 1\n1 2\n0 2\n' | python solution.py

# C++
g++ -std=c++17 -O2 solution.cpp -o bk && ./bk
```

> Windows / MinGW 下不要把編譯產物輸出到 `/tmp`（鏈接器會報 No such file or directory），
> 輸出到當前目錄或 `_build/` 即可。
