# 最小生成樹（Kruskal 算法 + 併查集）

| 語言 | 文件 |
|---|---|
| Python 3 | [`solution.py`](solution.py) |
| C++17 | [`solution.cpp`](solution.cpp) |

## 題意

給定 `n` 個點、`m` 條邊的**無向帶權圖**（頂點編號 `0..n-1`，邊權爲整數，可以爲負），求一棵**最小生成樹**：選出若干條邊把全部點連通，且邊權之和最小。若圖本身不連通（不存在生成樹），輸出 `disconnected`。

## 思路

Kruskal 是**貪心 + 併查集**：把所有邊按權值從小到大排序，依次嘗試加入；如果這條邊的兩個端點當前還不連通，就把它選進生成樹並合併兩端點所在的集合；否則這條邊會和已選的邊成環，直接丟棄。選夠 `n-1` 條邊就結束。

**爲什麼這樣是對的（切分性質）**：掃描到某條邊 `(u, v, w)` 且 `u`、`v` 尚未連通時，把「`u` 所在的連通塊」看作切分的一側。所有跨這個切分的邊裏，`(u, v, w)` 是當前未處理的最小者 —— 因爲更小的邊全都已經被考慮過了，它們要麼沒能跨這個切分，要麼會把點合併進來（那樣 `u`、`v` 就已經連通了）。跨切分的最小邊必然屬於某棵最小生成樹，所以選它不會錯。

併查集負責「`u`、`v` 是否已連通」的判定與合併，用路徑壓縮 + 按大小合併，均攤接近 O(1)。

> 排序必須**穩定**（同權邊保持輸入順序），這樣 Python 與 C++ 兩版輸出才能逐字節一致。C++ 裏用 `std::stable_sort` 只比較權值，Python 的 `sorted` 本身就是穩定的。

## 複雜度

| 項目 | 複雜度 |
|---|---|
| Kruskal 總時間 | O(m log m)（瓶頸在排序），併查集部分 O(m·α(n)) |
| Kruskal 空間 | O(n + m) |
| Prim（對照實現） | O(n² + m)，用鄰接表 + 線性掃最小 |
| 指數級枚舉（對照實現） | O(2^m · m)，僅用於極小規模測試 |

## 輸入輸出

```text
輸入：              輸出：
4 5                 6
0 1 1               0 1 1
0 2 4               1 2 2
1 2 2               2 3 3
1 3 5
2 3 3
```

- 輸入全部按空白分隔：`n m`，隨後 `m` 條邊 `u v w`（頂點 0-based）。
- 連通時：第一行爲最小生成樹的總權重，隨後每行一條被選中的邊 `u v w`，**按 Kruskal 的選中順序**輸出（權值升序，同權值按輸入順序）。
- 不連通時：只輸出一行 `disconnected`（不輸出任何邊）。
- 退化約定：`n = 0` 或 `n = 1` 視爲連通、權重 `0`；自環一定被丟棄；重邊只會留下其中一條。
- Python 與 C++ 版本的輸入輸出格式完全一致，同一輸入的輸出逐字節相同。
- 無 stdin 輸入時，兩個版本都會運行內置斷言測試並輸出 `all tests passed`。

## 測試覆蓋

固定用例：README 示例（4 點 5 邊 → 總權重 6）、不連通圖、空圖 / 單點、兩點無邊、自環與重邊、`n = 3` 全同權、負權邊（`[(0,1,-5), (1,2,-1), (0,2,10)]` → `-6`）、同權邊穩定順序。

隨機對拍：

1. 150 組小規模隨機圖（1–6 點、0–8 條邊），讓 **Kruskal、Prim、指數級枚舉**三者結論一致（總權重相等、連通性一致），並額外驗證選出的邊確實構成生成樹（`n-1` 條、併查集最終只有一個連通塊）。
2. 150 組**保證連通**的隨機圖（先隨機連成鏈再補隨機邊，最多 9 點），Kruskal 與 Prim 對拍總權重。
