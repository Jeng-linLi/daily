# 最小生成树（Kruskal 算法 + 并查集）

| 语言 | 文件 |
|---|---|
| Python 3 | [`solution.py`](solution.py) |
| C++17 | [`solution.cpp`](solution.cpp) |

## 题意

给定 `n` 个点、`m` 条边的**无向带权图**（顶点编号 `0..n-1`，边权为整数，可以为负），求一棵**最小生成树**：选出若干条边把全部点连通，且边权之和最小。若图本身不连通（不存在生成树），输出 `disconnected`。

## 思路

Kruskal 是**贪心 + 并查集**：把所有边按权值从小到大排序，依次尝试加入；如果这条边的两个端点当前还不连通，就把它选进生成树并合并两端点所在的集合；否则这条边会和已选的边成环，直接丢弃。选够 `n-1` 条边就结束。

**为什么这样是对的（切分性质）**：扫描到某条边 `(u, v, w)` 且 `u`、`v` 尚未连通时，把「`u` 所在的连通块」看作切分的一侧。所有跨这个切分的边里，`(u, v, w)` 是当前未处理的最小者 —— 因为更小的边全都已经被考虑过了，它们要么没能跨这个切分，要么会把点合并进来（那样 `u`、`v` 就已经连通了）。跨切分的最小边必然属于某棵最小生成树，所以选它不会错。

并查集负责「`u`、`v` 是否已连通」的判定与合并，用路径压缩 + 按大小合并，均摊接近 O(1)。

> 排序必须**稳定**（同权边保持输入顺序），这样 Python 与 C++ 两版输出才能逐字节一致。C++ 里用 `std::stable_sort` 只比较权值，Python 的 `sorted` 本身就是稳定的。

## 复杂度

| 项目 | 复杂度 |
|---|---|
| Kruskal 总时间 | O(m log m)（瓶颈在排序），并查集部分 O(m·α(n)) |
| Kruskal 空间 | O(n + m) |
| Prim（对照实现） | O(n² + m)，用邻接表 + 线性扫最小 |
| 指数级枚举（对照实现） | O(2^m · m)，仅用于极小规模测试 |

## 输入输出

```text
输入：              输出：
4 5                 6
0 1 1               0 1 1
0 2 4               1 2 2
1 2 2               2 3 3
1 3 5
2 3 3
```

- 输入全部按空白分隔：`n m`，随后 `m` 条边 `u v w`（顶点 0-based）。
- 连通时：第一行为最小生成树的总权重，随后每行一条被选中的边 `u v w`，**按 Kruskal 的选中顺序**输出（权值升序，同权值按输入顺序）。
- 不连通时：只输出一行 `disconnected`（不输出任何边）。
- 退化约定：`n = 0` 或 `n = 1` 视为连通、权重 `0`；自环一定被丢弃；重边只会留下其中一条。
- Python 与 C++ 版本的输入输出格式完全一致，同一输入的输出逐字节相同。
- 无 stdin 输入时，两个版本都会运行内置断言测试并输出 `all tests passed`。

## 测试覆盖

固定用例：README 示例（4 点 5 边 → 总权重 6）、不连通图、空图 / 单点、两点无边、自环与重边、`n = 3` 全同权、负权边（`[(0,1,-5), (1,2,-1), (0,2,10)]` → `-6`）、同权边稳定顺序。

随机对拍：

1. 150 组小规模随机图（1–6 点、0–8 条边），让 **Kruskal、Prim、指数级枚举**三者结论一致（总权重相等、连通性一致），并额外验证选出的边确实构成生成树（`n-1` 条、并查集最终只有一个连通块）。
2. 150 组**保证连通**的随机图（先随机连成链再补随机边，最多 9 点），Kruskal 与 Prim 对拍总权重。
