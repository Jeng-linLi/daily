# 凸包優化（Convex Hull Trick）與李超線段樹（Li Chao Segment Tree）

`2026-10-15/convex-hull-trick`

## 題意

給定 `k` 條直線 `y = m·x + b`、 `q` 個查詢點 `x`，以及一個長度 `n` 的陣列 `a`，回答三件事：

1. 對每個 `x`，求所有直線在 `x` 上的**最小值** —— 用**李超線段樹** O(log C)，並與 O(k) 暴力逐點驗證
2. 把直線依斜率排序後建**單調凸包**（deque），查詢點排序後 O(1) 均攤回答
3. **斜率優化 DP**：把 `a` 切成若干段，每段成本 = (段內元素和)² + `C`（`C = 10`），求最小總成本

```
dp[i] = min_{0 ≤ j < i} { dp[j] + (pre[i] - pre[j])² + C }，  dp[0] = 0
```

暴力 O(n²) 與李超線段樹 O(n log C) 互相驗證。

## 思路

### 為什麼需要「凸包優化」

一大類 DP 可以寫成

```
dp[i] = min_{j<i} { dp[j] + f(j)·g(i) + h(i) + w(j) }
```

把 `j` 視成一條直線：**斜率 `m_j = f(j)`、截距 `b_j = dp[j] + w(j)`**，
而 `i` 的轉移就是在 `x = g(i)` 上取所有直線的最小值。
於是把「O(n) 找最小值」換成「一堆直線求 min」，就有了優化的空間。

本題的 DP 展開後：

```
dp[i] = pre[i]² + min_{j<i} { (-2·pre[j])·pre[i] + (dp[j] + pre[j]² + C) }
                             └──── 斜率 m_j ────┘   └──── 截距 b_j ──────┘
```

### 李超線段樹：把「直線」當成區間上的懶標記

定義域 `x ∈ [L, R]` 建立在線段樹上，每個節點存一條「在該區間中點最優」的直線。插入新直線 `nw` 時，
跟節點當前的直線 `cur` 比中點：

- 若 `nw` 在中點更優 → **交換**，`nw` 變成「被擠掉的那一條」往下傳
- 若 `nw` 在左端點更優 → 它只可能在左半區間勝出，往左遞迴
- 否則若 `nw` 在右端點更優 → 往右遞迴
- 兩端都不優 → `nw` 在整個區間都被 `cur` 壓住，直接丟掉

正確性來自「**兩條直線最多交一次**」：在一個區間裡，若 `nw` 在兩端都輸給 `cur`，
則它在區間內部也不可能贏。每個節點只存一條線，插入 O(log C)、查詢 O(log C)。

優點是**完全不要求斜率或查詢點單調**；缺點是需要離散（或座標壓縮）的定義域。

### 單調凸包（dq-CHT）：斜率與查詢都單調時可以做到 O(1)

把直線依**斜率遞減**排列後建下凸包：斜率最大者在 `x → -∞` 時最優，斜率最小者在 `x → +∞` 時最優。
所以查詢點 `x` 遞增時，最佳直線在 hull 上的位置只會單調往前走，用一根指標就夠，全部查詢 `O(q + k)`。

- 加入：若最後兩條與新線的交點不滿足「交點遞增」，彈掉最後一條
- 查詢：若下一條比當前好，指標就前進（指標不回頭）

判斷「中間那條是不是多餘的」用整數交叉相乘，完全不碰浮點數（斜率遞減 `m₁ > m₂ > m₃`）：

```
交點順序亂掉 ⟺ (b₂ - b₁)(m₂ - m₃) ≥ (b₃ - b₂)(m₁ - m₂)
```

### 兩者的取捨

| 方法 | 要求 | 複雜度 | 備註 |
|---|---|---|---|
| 李超線段樹 | 無（任意順序、任意斜率） | O(log C) / 次 | 定義域要離散，程式稍長 |
| 單調凸包 | 斜率單調 + 查詢單調 | O(1) 均攤 / 次 | 常數極小，順序不對就不能用 |

實務上：DP 轉移順序天然單調時優先單調凸包；否則用李超。

## 複雜度（k 條線、q 次查詢、定義域寬度 C、DP 長度 n）

| 項目 | 時間 | 空間 |
|---|---|---|
| 李超線段樹插入 / 查詢 | O(log C) | O(k log C) |
| 單調凸包建構 | O(k log k)（排序）/ O(k)（已排序） | O(k) |
| 單調凸包全部查詢 | O(q + k) | O(1) |
| 斜率優化 DP | O(n log C)（李超）/ O(n)（單調凸包） | O(n log C) |

## 輸入格式（stdin，全部以空白分隔的整數）

```
k
m_1 b_1
...
m_k b_k
q
x_1 ... x_q
n
a_1 ... a_n
```

- 非數字 token 一律視為「輸入到此為止」；讀不滿的那一組直接丟棄
- `k ≤ 200`、`q ≤ 200`、`n ≤ 150`
- 斜率截斷到 `[-10^6, 10^6]`、截距到 `[-10^9, 10^9]`、查詢點到 `[-10^6, 10^6]`、`a_i` 到 `[-10^4, 10^4]`
- 李超線段樹定義域固定為 `x ∈ [-10^7, 10^7]`

## 輸出格式（6 行）

```
第 1 行  李超線段樹對每個查詢點 x 的答案（原始順序）
第 2 行  暴力（逐條線取 min）的答案（原始順序）
第 3 行  單調凸包對「排序後」的查詢點的答案
第 4 行  斜率優化 DP 的 dp[1..n]（李超）
第 5 行  斜率優化 DP 的 dp[1..n]（O(n²) 暴力）
第 6 行  1 = 第 1=2 行、第 3 行 = 該順序的暴力、第 4=5 行
```

## 範例

### 輸入

```
3
2 0
1 5
-1 10
4
-3 0 4 10
4
1 -2 3 4
```

### 輸出

```
-6 0 6 0
-6 0 6 0
-6 0 6 0
11 11 14 40
11 11 14 40
1
```

說明：三條線是 `y = 2x`、`y = x + 5`、`y = -x + 10`。
在 `x = -3` 時最小值是 `-6`（來自 `2x`）；`x = 0` 是 `0`；`x = 4` 是 `6`（來自 `-x+10`）；
`x = 10` 是 `0`。單調凸包只保留 `[(2,0), (-1,10)]` 兩條 —— 中間的 `y = x + 5`
在任何 `x` 上都取不到最小值，被判定為多餘。

DP 部分：`a = [1,-2,3,4]`，`dp = [11, 11, 14, 40]`
（例如 `dp[1] = 0 + 1² + 10 = 11`；`dp[2]` 取「`[1,-2]` 一段」得 `0 + (-1)² + 10 = 11`，
比切成兩段的 `11 + (-2)² + 10 = 25` 更便宜）。

## 邊界情況

- 沒有直線（`k = 0`）：所有查詢回傳整數哨兵 `4000000000000000000`
- 沒有查詢點（`q = 0`）：前 3 行為空行
- 沒有陣列（`n = 0`）：第 4、5 行為空行，`dp` 為空
- 同斜率的多條線：只保留截距最小的那條
- 查詢點超出 `[-10^6, 10^6]`：截斷後再算
