# 0-1 背包（Knapsack 0-1，动态规划）

| 语言 | 文件 |
|---|---|
| Python 3 | [`solution.py`](solution.py) |
| C++17 | [`solution.cpp`](solution.cpp) |

## 题意

有 `n` 个物品，第 `i` 个重量 `w[i]`、价值 `v[i]`，背包容量为 `W`。每个物品只能**选或不选**（不能切分、不能重复选），求能装下的最大总价值，并给出一种达到该价值的选取方案。

## 思路

定义 `dp[i][c]` = 只考虑前 `i` 个物品、容量为 `c` 时能取得的最大价值。对第 `i` 个物品只有两种决策：

- **不选**：`dp[i][c] = dp[i-1][c]`
- **选它**：`dp[i][c] = dp[i-1][c-w[i]] + v[i]`（要求 `c >= w[i]`）

取两者最大即为转移。由于物品只能选一次，转移**只依赖 `i-1` 层**，不会出现同层自我叠加——这正是它与「完全背包」的根本区别。

### 空间压缩与那个经典的坑

`dp` 可以压成一维 `dp[c]`，但**容量 `c` 必须倒序遍历**（`W → w[i]`）：

- 倒序时，`dp[c-w[i]]` 读到的仍是 `i-1` 层的旧值，正确；
- 正序时，`dp[c-w[i]]` 可能已经在本轮被更新过，同一物品被放了多次，直接退化成完全背包。

### 还原选取方案

一维表算得出最优值，但丢了决策轨迹，无法回溯。要输出方案必须保留**二维表**：从 `dp[n][W]` 反推，若 `dp[i][c] != dp[i-1][c]`，说明第 `i` 个物品被选中，跳到 `dp[i-1][c-w[i]]` 继续。

> 注意：最优解**不唯一**时（例如本仓库测试中 `w=[2,3,4,6], v=[3,4,5,7], W=10` 的最优值 12 有两条路径：选 `{4,6}` 或选 `{2,3,4}`），反推只会给出其中一条。测试里因此只断言「值最优 + 方案合法」，不锁死具体下标。

## 复杂度

| 版本 | 时间复杂度 | 空间复杂度 |
|---|---|---|
| 一维 `knapsackMax` | O(n·W) | O(W) |
| 二维 `knapsackWithItems` | O(n·W) | O(n·W) |

`W` 很大而 `n` 很小时，可改用「按价值定义状态」的 `dp[value] = 最小重量`，复杂度 O(n·Σv)。

## 输入输出

```text
输入：                       输出：
4 10                         12
2 3                          0 1 2
3 4
4 5
6 7
```

- 第一行 `n W`，接下来 `n` 行每行 `w_i v_i`。
- 输出第一行：最大总价值；第二行：被选中物品下标（0-based，升序，空格分隔；一个都没选则输出空行）。
- Python 与 C++ 版本的输入输出格式完全一致。
- 无 stdin 输入时，两个版本都会运行内置断言测试并输出 `all tests passed`。

## 测试覆盖

除固定用例（容量为 0、物品为空、单件装不下、零重量物品、贪心会选错的反例）外，两个版本都用**同一个固定随机种子**（20260922）生成 300 组随机数据，与指数级暴力枚举对拍，同时校验三件事：最优值与暴力一致、一维版与二维版一致、输出的方案不超容量且确实达到最优值。C++ 侧用同样的 LCG 复刻了 Python 的随机序列，两版跑的是同一批用例。
