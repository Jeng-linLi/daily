# 0-1 背包（Knapsack 0-1，動態規劃）

| 語言 | 文件 |
|---|---|
| Python 3 | [`solution.py`](solution.py) |
| C++17 | [`solution.cpp`](solution.cpp) |

## 題意

有 `n` 個物品，第 `i` 個重量 `w[i]`、價值 `v[i]`，背包容量爲 `W`。每個物品只能**選或不選**（不能切分、不能重複選），求能裝下的最大總價值，並給出一種達到該價值的選取方案。

## 思路

定義 `dp[i][c]` = 只考慮前 `i` 個物品、容量爲 `c` 時能取得的最大價值。對第 `i` 個物品只有兩種決策：

- **不選**：`dp[i][c] = dp[i-1][c]`
- **選它**：`dp[i][c] = dp[i-1][c-w[i]] + v[i]`（要求 `c >= w[i]`）

取兩者最大即爲轉移。由於物品只能選一次，轉移**只依賴 `i-1` 層**，不會出現同層自我疊加——這正是它與「完全背包」的根本區別。

### 空間壓縮與那個經典的坑

`dp` 可以壓成一維 `dp[c]`，但**容量 `c` 必須倒序遍歷**（`W → w[i]`）：

- 倒序時，`dp[c-w[i]]` 讀到的仍是 `i-1` 層的舊值，正確；
- 正序時，`dp[c-w[i]]` 可能已經在本輪被更新過，同一物品被放了多次，直接退化成完全背包。

### 還原選取方案

一維表算得出最優值，但丟了決策軌跡，無法回溯。要輸出方案必須保留**二維表**：從 `dp[n][W]` 反推，若 `dp[i][c] != dp[i-1][c]`，說明第 `i` 個物品被選中，跳到 `dp[i-1][c-w[i]]` 繼續。

> 注意：最優解**不唯一**時（例如本倉庫測試中 `w=[2,3,4,6], v=[3,4,5,7], W=10` 的最優值 12 有兩條路徑：選 `{4,6}` 或選 `{2,3,4}`），反推只會給出其中一條。測試裏因此只斷言「值最優 + 方案合法」，不鎖死具體下標。

## 複雜度

| 版本 | 時間複雜度 | 空間複雜度 |
|---|---|---|
| 一維 `knapsackMax` | O(n·W) | O(W) |
| 二維 `knapsackWithItems` | O(n·W) | O(n·W) |

`W` 很大而 `n` 很小時，可改用「按價值定義狀態」的 `dp[value] = 最小重量`，複雜度 O(n·Σv)。

## 輸入輸出

```text
輸入：                       輸出：
4 10                         12
2 3                          0 1 2
3 4
4 5
6 7
```

- 第一行 `n W`，接下來 `n` 行每行 `w_i v_i`。
- 輸出第一行：最大總價值；第二行：被選中物品下標（0-based，升序，空格分隔；一個都沒選則輸出空行）。
- Python 與 C++ 版本的輸入輸出格式完全一致。
- 無 stdin 輸入時，兩個版本都會運行內置斷言測試並輸出 `all tests passed`。

## 測試覆蓋

除固定用例（容量爲 0、物品爲空、單件裝不下、零重量物品、貪心會選錯的反例）外，兩個版本都用**同一個固定隨機種子**（20260922）生成 300 組隨機數據，與指數級暴力枚舉對拍，同時校驗三件事：最優值與暴力一致、一維版與二維版一致、輸出的方案不超容量且確實達到最優值。C++ 側用同樣的 LCG 復刻了 Python 的隨機序列，兩版跑的是同一批用例。
