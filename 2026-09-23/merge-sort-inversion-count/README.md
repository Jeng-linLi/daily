# 归并排序与逆序对计数（Merge Sort & Inversion Count）

| 语言 | 文件 |
|---|---|
| Python 3 | [`solution.py`](solution.py) |
| C++17 | [`solution.cpp`](solution.cpp) |

## 题意

给定长度为 `n` 的整数序列 `a`，求其中「逆序对」的个数，即满足 `i < j` 且 `a[i] > a[j]` 的二元组 `(i, j)` 的数量，并输出升序排序后的序列。

## 思路

暴力做法是双重循环 `O(n²)`。归并排序能顺手把逆序对数出来，是因为逆序对天生可以按「分治三分类」拆解：对区间 `[lo, hi)` 以 `mid` 切分后，任意一个逆序对 `(i, j)` 恰好属于下面三类之一，**不重不漏**：

1. `i, j` 都在左半边 → 递归统计
2. `i, j` 都在右半边 → 递归统计
3. `i` 在左半边、`j` 在右半边 → **跨中线的逆序对**

关键在第 3 类。合并两个「已各自有序」的子数组时，一旦出现 `arr[i] > arr[j]`，由于左半边 `arr[i..mid)` 是升序的，`arr[i]` 及其后面所有元素都 `≥ arr[i] > arr[j]`，于是它们与 `arr[j]` 一次性构成 `mid - i` 个逆序对。

```text
左半边（已升序）:  ... arr[i] arr[i+1] ... arr[mid-1]
右半边（已升序）:  ... arr[j] ...
若 arr[i] > arr[j]，则 arr[i..mid-1] 全部 > arr[j]  →  一次结算 (mid - i) 个
```

一次比较结算一整段，这就是把 `O(n²)` 压到 `O(n log n)` 的来源。

### 两个容易写错的点

- **比较要取等号**：必须写成 `arr[i] <= arr[j]` 才走左半边。若写成 `<`，相等元素会被误判成逆序对，违背「逆序对 = 严格大于」的定义。归并排序是否稳定，也就取决于这个等号的方向。
- **计数要用 64 位**：逆序对的上界是完全逆序时的 `n(n-1)/2`，`n = 65536` 就已超过 `int` 范围。C++ 侧用 `long long`。

### 一个有用的等价视角

逆序对个数 **恰好等于** 「只允许交换相邻元素」时把序列排好序所需的最少交换次数 —— 也就是冒泡排序的交换次数。因为一次相邻交换最多消去一个逆序对，而冒泡排序每次交换都恰好消去一个。

## 复杂度

| 版本 | 时间复杂度 | 空间复杂度 |
|---|---|---|
| 归并统计 `sortAndCount` | O(n log n) | O(n)（辅助数组） |
| 暴力 `countInversionsBrute` | O(n²) | O(1) |

归并排序的时间复杂度与输入数据的有序程度无关，最好/最坏/平均都是 `O(n log n)`（快排在最坏情况下会退化到 `O(n²)`）。

## 输入输出

```text
输入：              输出：
5                   5
2 3 8 6 1           1 2 3 6 8
```

- 第一行 `n`，第二行 `n` 个整数（可跨行书写）。
- 输出第一行：逆序对个数；第二行：升序排序后的序列（空格分隔；`n = 0` 时输出空行）。
- 上例中 5 个逆序对分别是 `(2,1) (3,1) (8,6) (8,1) (6,1)`。
- Python 与 C++ 版本的输入输出格式完全一致。
- 无 stdin 输入时，两个版本都会运行内置断言测试并输出 `all tests passed`。

## 测试覆盖

固定用例：空序列、单元素、已升序（0 个）、完全逆序（10 个）、相等元素不算逆序对、负数与零、`n = 2000` 的完全逆序（验证 `long long` 不溢出）。

随机对拍：两版各自用固定种子（20260923）生成 300 组长度 0–40、值域 `[-20, 20]` 的随机序列，与 `O(n²)` 暴力枚举对比，同时校验逆序对数一致、排序结果与标准库一致、元素个数不变；另外验证排序不会改动调用方传入的原数组/列表。
