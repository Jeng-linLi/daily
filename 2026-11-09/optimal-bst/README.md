# 最優二叉搜尋樹 Optimal BST（Knuth 四邊形不等式優化）

## 題意

n 個已排序的鍵 1..n，第 i 個鍵被搜尋的權重為 `p[i]`。建一棵二叉搜尋樹（中序遍歷恰為 1..n），第 i 個鍵位於深度 `depth(i)`（根為 1），總成本

```
cost = Σ_{i=1..n} p[i] × depth(i)
```

求**最小總成本**與**整棵樹的根編號**（1-based，平手取編號最小者）。

## 思路

### 樸素區間 DP（O(n³)）

令 `w[i][j] = Σ_{k=i..j} p[k]`（前綴和遞推），`dp[i][j]` 為鍵 i..j 建成子樹的最小成本：

```
dp[i][j] = min_{r=i..j} { dp[i][r-1] + dp[r+1][j] } + w[i][j]
```

`w[i][j]` 這一項的幾何意義：無論選誰當根，區間內所有鍵的深度都整體 +1，所以每層統一加上 `w[i][j]`。

### Knuth 優化（O(n²)）

權重 `w` 滿足**四邊形不等式**（QI：`w[a][c] + w[b][d] ≤ w[a][d] + w[b][c]`，a ≤ b ≤ c ≤ d）與**區間單調性**（`w[b][c] ≤ w[a][d]`），可以證明最優根位置 `s[i][j]` 滿足**決策單調性**：

```
s[i][j-1] ≤ s[i][j] ≤ s[i+1][j]
```

於是列舉根時只需在這個窗口內找。雖然單個狀態窗口最壞 O(n)，但對固定長度，窗口總長 ≤ n，均攤後每個狀態 O(1) 次比較，總複雜度 **O(n²)**（樸素 O(n³) 在 n=3000 時約 9×10⁹ 次運算，Knuth 版約 9×10⁶）。

## 複雜度

- 時間：O(n²)（Knuth）；對拍暴力 O(n³)
- 空間：O(n²)

## IO 示例

```
輸入：          輸出：
4               18
2 3 1 4         2
```

權重 `[2,3,1,4]` 的最優 BST 以鍵 2 為根：左子樹 {1}（深度 2）、右子樹 {3,4}（3 為 4 的父親），成本 `2×2 + 3×1 + 1×3 + 4×2 = 4+3+3+8 = 18`。整樹根為 2。

```
輸入：          輸出：
0               0 0
```

## 驗證

- 無 stdin 時跑內建斷言：Knuth O(n²) 與樸素 O(n³) 隨機對拍 300 組（成本必須相等，且 Knuth 選出的根代入後成本確實最優）、s 陣列決策單調性檢查 50 組。
- Python 與 C++ 的 stdin/stdout 對拍 65 組（含 n=0、n=1、全 0 權重、大權重 10⁹、n=3000 上限）逐字節一致。
