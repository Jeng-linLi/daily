# K-D Tree（2 維空間搜尋樹）

`solution.py`（Python 3 標準庫）與 `solution.cpp`（C++17）行為完全一致：
有 stdin 走 IO 模式，沒有 stdin 就跑內置斷言並輸出 `all tests passed`。

---

## 題意

給平面上 n 個點，建一棵 **2-d tree**，支援五種空間查詢，並與 O(n) 暴力掃描
逐項對拍，確保每一次剪枝都沒剪掉真正的答案。

| 操作碼 | 參數 | 說明 |
|---|---|---|
| 1 | `qx qy` | 最近鄰：輸出「距離平方 點編號」（平手取編號最小） |
| 2 | `qx qy k` | k 近鄰：輸出前 k 個距離平方（升序；不足補 -1） |
| 3 | `x1 y1 x2 y2` | 矩形範圍計數（邊界含在內） |
| 4 | `qx qy r` | 半徑計數：距離平方 ≤ r² 的點數 |
| 5 | `qx qy x1 y1 x2 y2` | 帶矩形約束的最近鄰（只考慮落在矩形內的點） |

## 輸入格式

```
n                    點數（0 ≤ n ≤ 400；負數視為 0）
x y                  n 行，每行一個點
q                    查詢數（0 ≤ q ≤ 200；負數視為 0）
op ...               q 行，每行一個查詢
```

全部 token 以空白分隔；遇到非整數 token 就當成「輸入到此為止」，缺值補預設。
座標會被夾到 `[-10^6, 10^6]`，半徑夾到 `[0, 3·10^6]`，k 夾到 `[1, 8]`。
op 不在 1..5 的查詢直接忽略。

## 輸出格式

```
第 1..q 行：每個查詢一行結果
第 q+1 行 ：ok 旗標（1 = k-d tree 的答案與 O(n) 暴力掃描完全一致）
```

逐步解釋（點的編號是 0-based 輸入順序）：

| 查詢 | 說明 | 結果 |
|---|---|---|
| `1 0 0` | 最近鄰 | 點 0 `(0,0)`，距離 0 |
| `1 3 4` | 最近鄰 | 點 1 `(3,4)`，距離 0 |
| `2 0 0 3` | 3 近鄰 | 距離 0（點 0）、2（點 4 `(1,1)`）、25（點 1 `(3,4)`） |
| `3 -10 -10 2 2` | 矩形計數 | 點 0、3 `(-5,2)`、4 `(1,1)` → 3 個 |
| `4 0 0 5` | 半徑 5 | 距離 ≤ 25：點 0（0）、點 4（2）、點 1（25） → 3 個 |
| `5 0 0 -10 -10 2 2` | 矩形內最近鄰 | 點 0，距離 0 |

邊界輸入：

```

輸入 "0\n2\n1 0 0\n3 0 0 0 0"    →  輸出 "-1 -1\n0\n1\n"    （空點集：查不到東西）
```

## 思路

### 1. 為什麼二分空間也能「二分搜尋」

BST 是對**一維**鍵值二分；k-d tree 把它推廣成輪流對**各個維度**二分。
本題在 2D：每次建節點時，看當前這群點在哪個維度上**散得最開**（spread 最大），
就沿那個維度排序取中位數切開——這樣切出來的「格子」最接近正方形，剪枝效果最好。

```
axis = (spread_x >= spread_y) ? x : y        // 平手時固定選 x
mid  = 排序後的中位數 → 當節點；左半、右半各遞迴
```

（固定輪流切 x / y 也可以，但遇到狹長分佈（例如全部點擠在一條斜線上）會退化。）

每個節點額外存**這棵子樹所有點的包圍盒**（bounding box，4 個數字）。
有了包圍盒，就能算出「查詢點到這整棵子樹的**最小可能距離**」：

```
dx = (qx < minx) ? minx - qx : (qx > maxx ? qx - maxx : 0)
dy = 同理
minDist = dx² + dy²
```

這正是剪枝的依據。

### 2. 最近鄰的剪枝（本題核心）

遞迴時先走「離查詢點比較近」的那一邊（比較兩邊包圍盒的 `minDist`），
拿到一個候選答案 `best` 之後，再決定另一邊要不要走：

```
若 minDist(查詢點, 另一邊的包圍盒) > best  →  整棵子樹不可能更近，剪掉
```

**注意必須是 `>` 才剪（不是 `>=`）**：平手時我們要取**編號最小**的點，
所以距離相等的子樹仍必須進去看一眼。這是兩語言要一致的第一個細節。

### 3. k 近鄰

維護一個大小 k 的有序緩衝區，第 k 名就是當前的「門檻」。
剪枝條件一樣用 `>`：包圍盒最小距離**等於**門檻時仍要進去，
因為可能存在「距離一樣但編號更小」的點，會把目前的第 k 名擠掉。

```
thresh = (緩衝區已滿 k 個) ? 第 k 名的距離 : +∞
if (minDist(子樹) <= thresh) 才遞迴進去
```

每走到一個節點就把 `(距離, 編號)` 丟進緩衝區、排序、截斷到 k 個。
k ≤ 8，排序的常數代價可以接受。

### 4. 矩形 / 半徑計數

- **矩形**：若子樹包圍盒與查詢矩形**無交集**就直接剪掉；否則遞迴兩邊。
- **半徑**：若 `minDist(子樹) > r²` 就剪掉；否則遞迴兩邊。

這兩個是「範圍搜尋」，複雜度與輸出大小有關，不像最近鄰那麼漂亮，
但實務上仍然快很多。

### 5. 兩語言一致性的三個細節

1. 切分維度平手時固定選 x（`spread_x >= spread_y` → axis 0）。
2. 排序鍵必須是 `(該維度座標, 點編號)` 這種**全序**，不能只比座標，
   否則座標相同的點順序在兩邊可能不同，中位數就換人，整棵樹的形狀跟著不同。
3. 矩形查詢先把 `x1 > x2`、`y1 > y2` 的輸入正規化（swap），
   半徑先夾到非負，避免兩個語言對「退化矩形」有不同解讀。

### 6. 複雜度：是「期望」不是「最壞」

k-d tree 的查詢在點均勻分佈時是 O(log n)；但遇到點全落在圓周上、
或查詢點離所有點都很近的最壞情況，仍會退化成 O(n)。
要嚴格的最壞對數複雜度得用 R-tree / BVH / Voronoi 圖，
不過實務上 k-d tree 因為常數極小、又好寫，仍是第一選擇。

---

## 複雜度

| 項目 | 複雜度 | 說明 |
|---|---|---|
| 建樹 | O(n log² n) | 每層排序一次；改用 `nth_element` 可降到 O(n log n) |
| 最近鄰 | 平均 O(log n)，最壞 O(n) | 取決於剪枝效果 |
| k 近鄰 | 平均 O(k log n) | 緩衝區排序是 O(k log k) |
| 矩形 / 半徑計數 | 平均 O(√n + 輸出數)，最壞 O(n) | 2D 下橫越的格子數約 O(√n) |
| 空間 | O(n) | 每個節點存編號、兩個小孩、4 個座標 |

## 應用場景

- **地理資訊系統**：外送 / 打車配對「最近的司機」、附近餐廳搜尋、電子圍欄判斷
- **機器學習**：kNN 分類與迴歸；DBSCAN 等密度聚類的鄰域查詢加速
- **電腦圖學**：光線追蹤的加速結構（k-d tree 是 BVH 的老前輩）、碰撞檢測的 broad phase
- **電腦視覺**：SIFT / ORB 特徵點的最近鄰匹配（OpenCV 的 FLANN 底層就有 k-d tree）
- **天文學**：星表交叉比對（cross-match），把兩份上百萬筆的星表對起來
- **物理模擬**：SPH、分子動力學的鄰居清單（neighbor list）維護

## 怎麼跑

```bash
# Python（無 stdin → 跑內置斷言）
python solution.py

# Python（有 stdin → IO 模式）
printf '3\n0 0\n3 4\n1 1\n2\n1 0 0\n3 -5 -5 5 5\n' | python solution.py

# C++
g++ -std=c++17 -O2 solution.cpp -o kd && ./kd
```

> Windows / MinGW 下不要把編譯產物輸出到 `/tmp`（鏈接器會報 No such file or directory），
> 輸出到當前目錄或 `_build/` 即可。
