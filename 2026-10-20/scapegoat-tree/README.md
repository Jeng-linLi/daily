# 替罪羊樹（Scapegoat Tree）

`solution.py`（Python 3 標準庫）與 `solution.cpp`（C++17）行為完全一致：
有 stdin 走 IO 模式，沒有 stdin 就跑內置斷言並輸出 `all tests passed`。

---

## 題意

維護一個**有序集合**（元素唯一），支援七種操作，並與「有序陣列 + 二分」
的參考實作逐項對拍，確保每一個答案都正確。

| 操作碼 | 名稱 | 說明 |
|---|---|---|
| 1 | `insert x` | 插入 x（已存在則忽略） |
| 2 | `erase x` | 刪除 x，不存在則忽略 |
| 3 | `count x` | x 是否在集合中（1 / 0） |
| 4 | `rank x` | 嚴格小於 x 的元素個數 |
| 5 | `kth k` | 第 k 小的元素（k 從 1 起算），越界回傳 -1 |
| 6 | `pred x` | 嚴格小於 x 的最大元素，不存在回傳 -1 |
| 7 | `succ x` | 嚴格大於 x 的最小元素，不存在回傳 -1 |

## 輸入格式

```
q                    操作數（0 ≤ q ≤ 300；負數視為 0）
op x                 q 行，每行一個操作
```

全部 token 以空白分隔；遇到非整數 token 就當成「輸入到此為止」，缺值補預設。
`op` 不在 1..7 的操作直接忽略；`x` 會被夾到 `[0, 10^6]`
（這樣 `-1` 才能安全地當作「不存在」的哨兵）。

## 輸出格式（共 3 行）

```
第 1 行：所有查詢（op ≥ 3）的結果，以空格分隔；沒有查詢就是空行
第 2 行：size、樹高，以及排序後的全部元素，以空格分隔
第 3 行：ok 旗標（1 = 替罪羊樹與有序陣列參考實作完全一致）
```

## 輸入輸出示例

輸入：

```
10
1 5
1 3
1 7
3 3
4 5
5 2
6 4
7 4
2 3
5 1
```

輸出：

```
1 1 5 3 5 5
2 2 5 7
1
```

逐步解釋：

| 步驟 | 集合 | 結果 |
|---|---|---|
| insert 5 / 3 / 7 | {3, 5, 7} | — |
| count 3 | | 1 |
| rank 5 | | 1（只有 3 比 5 小） |
| kth 2 | | 5 |
| pred 4 | | 3 |
| succ 4 | | 5 |
| erase 3 | {5, 7} | — |
| kth 1 | | 5 |

最終 `size = 2`、樹高 2、排序後 `[5, 7]`。

邊界輸入：

```
輸入 "0"        →  輸出 "\n0 0\n1\n"   （沒有操作：沒有查詢、size 0、樹高 0）
輸入 "2 9 0"    →  輸出 "\n0 0\n1\n"   （op 9 不在 1..7，整行被忽略）
```

> 完全空白的 stdin 會走「跑內置斷言」分支，輸出 `all tests passed`。

## 思路

### 1. 什麼是「權重平衡」

紅黑樹 / AVL / Treap / Splay 都靠**旋轉**（rotation）局部調整形狀。
替罪羊樹完全不旋轉，改成一個更粗暴的條件：

```
對每個節點 u，其左右子樹大小都必須 ≤ α · size(u)      （本題 α = 7/10）
```

一旦某個節點違反這個條件，就把它的**整棵子樹**拉直（中序遍歷成有序陣列），
再從中點遞迴建成一棵完美平衡樹。這個動作叫 **rebuild（重建）**。

之所以叫「替罪羊」：插入一個新節點可能讓整條路徑上的祖先都失衡，
但我們不需要處罰每一個祖先——只要抓出**一個**來重建就夠了。

### 2. 為什麼這樣還能是 O(log n)

- **樹高**：α 權重平衡 ⟹ 從根往下每走一層，子樹大小至少縮為 α 倍
  ⟹ 樹高 ≤ `log_{1/α}(n)` = `ln n / ln(10/7)` ≈ `2.81 · log₂ n`。
- **攤還代價**：一個節點被重建，代表它底下剛累積了 Θ(size) 次插入
  （每次插入最多讓子樹大小 +1，要從「平衡」長到「失衡」得累積這麼多次）。
  於是把 O(size) 的重建成本分攤到這 Θ(size) 次插入上，每次插入攤還 O(log n)。

### 3. 插入後要重建「哪一個」節點（本題的關鍵設計）

插入後從根沿著 key 走一趟，找**最淺**（離根最近）的那個失衡節點 v 重建。
重建完之後：

- `subtree(v)` 內部全部完美平衡（建法是從中點遞迴，每個節點的兩個小孩最多差 1）；
- v 的祖先們**大小完全沒變**（重建不改變節點數），
  所以「下一次失衡的位置」只能嚴格地往根的方向移動。

於是把這個動作寫成迴圈：

```
while 存在失衡節點 v（取最淺的）:  rebuild(v)
```

每一輪 v 的位置嚴格變淺，最多走 depth 輪就結束；一旦 v 就是根，
重建後整棵樹完美平衡，必然收斂。

> 為什麼不「只重建一次」或「重建最深的」？
> 插入會讓祖先的 `size` 與子樹 `size` **同時 +1**，而 α < 1：
> `child ≤ α·size` 成立時，`child+1 ≤ α·(size+1) = α·size + α` **未必**成立（因為 1 > α）。
> 也就是說修好下面那一層，可能反而把上面那一層弄壞。
> 反覆「取最淺的失衡節點」是唯一能保證收斂到全域平衡的寫法。

### 4. 刪除：靠「縮水太多就整棵重建」

刪除走一般 BST 刪除：

- 葉子或只有一個小孩 → 直接把小孩接上去；
- 兩個小孩 → 用**中序前驅**（左子樹最大值）的值頂替，再遞迴刪掉那個前驅。

沿途把 `size - 1`。接著維護 `max_size`（歷史最大節點數）：
當 `size · 10 < max_size · 7` 時，表示節點已經掉到歷史高峰的 70% 以下，
整棵樹重建並把 `max_size` 設回 `size`。攤還起來每次刪除也是 O(log n)。

### 5. 兩語言一致性的兩個陷阱

- 平衡條件用**整數**比較 `max(l, r) · 10 > size · 7`，不要用浮點 α。
- 建平衡樹取中點用 `mid = (l + r) // 2`。下標非負時 Python 的 floor `//`
  與 C++ 的 truncate `/` 結果相同；一旦座標可能為負就會分道揚鑣（C++ 甚至會造出 `l > r` 的區間）。

### 6. size 欄位的不變量檢查

本題在每一輪對拍結束時，額外用 `true_size()` 實際走一趟，
確認每個節點的 `size` 欄位等於真實子樹大小。
這是必要的：中序遍歷的內容就算完全正確，`size` 算錯仍然會讓 `kth` / `rank` 給錯答案
（本次開發就是靠這個檢查抓出「兩個小孩的刪除忘記更新祖先 size」的 bug）。

## 複雜度

| 操作 | 時間 | 說明 |
|---|---|---|
| 查找 / `rank` / `kth` / `pred` / `succ` | O(log n) 最壞 | 樹高有保證 |
| 插入 | 攤還 O(log n) | 單次最壞 O(n)（重建整條路徑） |
| 刪除 | 攤還 O(log n) | 單次最壞 O(n)（全域重建） |
| 樹高 | ≤ `log_{1/α}(n) + O(1)` ≈ `2.81 · log₂ n` | α = 0.7 |
| 空間 | O(n) | 每個節點只存 key / 兩個小孩 / size |

---

## 應用場景

- **想避開旋轉邏輯的場合**：紅黑樹的插入刪除有 5 種 case，替罪羊樹只有「重建」一件事，
  程式碼量少一個數量級，很適合教學與快速原型
- **函數式 / 持久化結構**：重建天然產生新節點，不需要可變指標，對 GC 語言友善
- **資料庫索引**：「批次重建」比「逐次旋轉」快的場景，例如 LSM-tree 的 read-only segment 合併
- **嵌入式 / 即時系統**：旋轉會讓外部持有的指標或迭代器失效，重建雖然慢但語義單純、可預期
- 競賽中 Treap / Splay 的替代寫法，特別是需要「按子樹大小攤平」的題目

## 怎麼跑

```bash
# Python（無 stdin → 跑內置斷言）
python solution.py

# Python（有 stdin → IO 模式）
printf '4\n1 5\n1 3\n3 3\n4 5\n' | python solution.py

# C++
g++ -std=c++17 -O2 solution.cpp -o sg && ./sg
```

> Windows / MinGW 下不要把編譯產物輸出到 `/tmp`（鏈接器會報 No such file or directory），
> 輸出到當前目錄或 `_build/` 即可。
